# Jw Assistant — 실행 로드맵 v0.2

작성일 2026-09-22. 개정 2026-09-24. [제품 계획 v0.2](product-plan-v2.md)의 근거를 반영한다. 달력은 자료·환경·검증 게이트가 확보된다는 전제의 계획이며 납기 보장이 아니다. 실도면·Windows 실기 결과가 우선한다.

## 1. 지금 개발할 MVP: 읽기 전용 점검과 검토 기록

| 스프린트 | 주요 결과 | 병렬 분담 | 완료 게이트 |
|---|---|---|---|
| S0 — 완료 | 합성 검사/미리보기, 진단 capture 도구, 디자인 기초 | 초기 SOL/TERRA, 이후 GPT-6 Sol/Luna 보완 | [기존 보고](sprint-00-report.md); 실제 Jw 호출/쓰기 없음 |

호환성 실패를 일정 때문에 통과 처리하지 않는다. 쓰기와 AI는 별도 게이트이며 읽기 전용 파일럿의 선행 조건이 아니다. preview 승인 UI만으로 안전한 CAD 쓰기가 구현된 것은 아니다. 파일럿은 I2부터 시작해 후속 기능의 시간·오탐·검토 비용도 다시 측정한다.

I2의 패키지는 제한된 파일럿용 설치/제거 안내와 검증된 실행 묶음이다. 일반 사용자 권한에서 설치가 막히면 해당 사무소에 배포하지 않는다. 정식 서명·업데이트 채널·조직 배포는 I4 제품 게이트로 구분한다. I2의 수동 RevisionTask가 P0이고 I3은 같은 작업에 AI 초안을 추가한다.

### 다음 구현 I1의 작업 티켓

2026-09-25 I1B 상태: [스프린트 보고](sprint-03-i1b-report.md). 수동 세션 디렉터리 준비, 완료 metadata 공개, 브라우저 pair 검증을 구현하고 Node 32개 및 Windows 두 검사 스크립트가 통과했다. 두 실제 Jw 창의 동시 실행은 미검증이다. UTF-8 BOM 후보는 선택창 인식만 확인했고 실행은 미검증이다. 아래 I1 실기 게이트를 완료 처리하지 않는다. 다음 I2 티켓과 합격 조건은 보고서에 구체화했다.

## 2. 1년 내 제품

| 시기 | 고객에게 생기는 기능 | 선행 데이터 / 게이트 |
|---|---|---|
| 0~2개월 | 실제 읽기 전용 점검·회사 프로필·검토 이력, 초기 파일럿 | 기존 방식 대비 효용, Windows 설치/취소/복구 |
| 2~4개월 | 수정 지시 AI·BYOK, 제한된 정리 writer, 공급자 추가 | task 평가·전송·비용 게이트와 writer 게이트를 독립 통과 |
| 4~6개월 | 출도 manifest·지정 표제란/목록·변경대장, text/arc | 형식별 golden·기관 규칙·문자/축척·미지원 표시 |
| 6~9개월 | 확정된 建具/입면/표 링크, 사내 상세 검색 | semantic link·중복 ID·문서 출처·권한 |
| 9~12개월 | 한정 자동치수/부품 배치·근거 있는 수량 CSV·사무소 gateway | 실무 수요, deterministic 작도, 비용/운영 책임 |

도면 세트 검토를 하려면 여러 snapshot을 의도적으로 수집하거나 JWW parser를 별도 확보해야 한다. 단일 선택 데이터로 프로젝트 전체를 이해한다고 설명하지 않는다. parser 후보는 라이선스, 유지보수, 버전별 원본 재개방, 손실 보고를 평가한 뒤 채택한다.

PDF/OCR은 독립 입력 adapter다. 처음에는 지시문 붙여넣기·사용자 지정 span을 사용하고, native text·스캔·손글씨를 같은 정확도로 취급하지 않는다. 기관 제출과 외부 메시지 자동 발송은 첫 제품에 포함하지 않는다.

## 3. 장기 AI 설계 플랫폼

검증된 의미 객체와 관계를 토대로 변경 영향, 평면↔입면↔단면↔建具表 정합성, 근거 있는 수량 산출, 회사 표준 상세 재사용으로 확장한다. 법규·구조 엔진은 별도 전문가 승인·버전 관리 게이트를 둔다. 최종적으로 Jw, Excel, 문서 adapter가 동일한 project graph와 approval/event 기록을 사용한다.

AutoCAD/Revit/ARCHICAD 구현은 지금 만들지 않는다. 공통 domain과 `CadAdapter` capability 경계만 둔다. 미래 adapter의 영속 ID·단위·Undo 능력은 각 CAD의 계약에 맞게 구현한다. Jw의 낮은 수준 데이터를 모든 CAD에 강요하지 않는다.

## 4. 병렬 개발 운영

- 루트: 요구사항과 계약 소유, 작업 분해, 통합, 실제 시험, 스프린트 판정과 보고.
- GPT-6 Sol: 파일 형식·기하·transaction·장애 회귀처럼 정확성 검토가 중요한 작업.
- GPT-6 Luna: 계약이 고정된 UI 구현·번역·프로필 편집·검사 도구·문서 보완.
- 이 배치는 2026-09-23 사용자의 모델 변경 요청을 반영한다. 초기 조사와 시제품 작성에 사용한 GPT-5.6 SOL·TERRA의 결과는 보존하여 인계했다.
- JEV: 제품 후보 순위 adapter의 후속 실험. 개발 에이전트나 빠른 기하 계산 엔진으로 간주하지 않음.

한 agent는 명시된 파일/모듈만 수정한다. 공통 계약 변경은 루트와 소비자에게 먼저 전달한다. 필요한 파일을 독립적으로 작업할 때만 병렬화한다. 리뷰 완료 뒤 관련 시험만 수행하고 동일 시험을 근거 없이 반복하지 않는다.

## 5. 실제 Jw 합격 fixture

다음은 완료한 시험 목록이 아니라 **실기 수락 계획**이다.

| ID | 입력 / 동작 | 확인 결과 |
|---|---|---|
| JG-01 | 설치된 Jw의 버전과 공식 최신판 비교 | exact version, exe hash, OS 기록 |
| JG-02 | 1000mm 선, 1:1과 1:50 | 좌표·hs·원점 관계 확정 |
| JG-03 | 서로 다른 그룹 1:50 / 1:100 + 축각 | 그룹 전환·변환 정확성 |
| JG-04 | 선·호·원·점·문자·solid·polyline·block 각각 | 지원/미지원 범위와 원시 레코드 |
| JG-05 | 일본어/ASCII, Shift-JIS·UTF-8 BAT, BOM 변형 | decode/encode 무손실, codec 선언 |
| JG-06 | 동일 선 두 개, 교차층·색·선종 차이 | occurrence ID와 정확 중복 삭제 경계 |
| JG-07 | identity transform, 소수 좌표 | 개수·속성·bbox·문자·정밀도 보존 |
| JG-08 | preview 취소·창닫기·helper crash·timeout | Jw와 입력 파일 불변 |
| JG-09 | hd 반환 후 Undo 한 번 및 Redo | 전체 복원 여부, 대량 한계; 실패 시 write release 차단 |
| JG-10 | 공백·일본어 경로, 읽기전용·lock·동시 두 세션 | 경로 격리, 충돌 탐지, 실패 시 무변경 |
| JG-11 | 오류 출력·unknown record·stale hash·중복 승인 | 출력 미적용, 재검사 안내 |
| JG-12 | 양 언어, 키보드, IME, Narrator, DPI | 일본 실무자가 핵심 task를 수행 |
| JG-13 | 새 선택에 이전 이슈가 없음 / 대응 모호 | 미관찰·재확인 상태, 자동 해결 금지 |
| JG-14 | 규칙·profile 변경, 예외, migration | 이전 판단 재확인과 로컬 복구 가능 |

API 평가와 실패 시나리오는 [AI 작업 계약](ai-workflows.md), [합성 평가 사례](evals/seed-cases.json), [파일럿 계획](pilot-plan.md)을 따른다. 계획된 사례 수는 통과한 시험 수가 아니다.

## 6. 보고 규칙

모든 스프린트마다 `sprint-NN-report.md`를 남기고 사용자에게 링크와 핵심 결과를 보고한다. 보고는 실제 실행 범위, 데모 경로, 시험 명령/결과, 미검증·실패, 새로 확정한 결정, 다음 게이트를 포함한다. 계획한 기능과 완료한 기능을 섞지 않는다. CI 통과를 실도면 또는 사용자 검증으로 대체하지 않는다.

이번 작업은 예약된 자동 실행이 아니다. 다음 스프린트에서 같은 문서와 계약을 이어 사용한다. 사용자가 별도로 요청하지 않은 일정 알림이나 백그라운드 모니터는 만들지 않는다.

## 2026-09-25 현장 요구사항 보강

상세 레이어 34개 초기 분류와 명시적 대응표, 마감 인계 12개 항목의 누락 검사, 문맥별 메모를 읽기 전용으로 구현했다. [현장 계약](field-coordination.md)과 [Sprint 04](sprint-04-i2a-report.md)를 현재 범위의 기준으로 삼는다. 다음은 복수 위치 카드, 미저장 전환 안내, 복구 UI와 실무자 매핑 검증이다. 실제 CAD 레이어 생성/분리·마감 작도는 host 쓰기 및 Undo 게이트 후 진행한다. 스프린트별 기능 커밋과 GitHub 푸시를 수행하며 개인 참조 자료는 제외한다.
