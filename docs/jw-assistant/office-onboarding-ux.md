# Office onboarding UX proposal

상태: **미구현 제품 제안** (2026-09-23)
대상: 일본 Windows 사무소, 우선 일본어 UI. 영어는 같은 화면의 대체 locale.

이 제안은 [product-plan-v2.md](product-plan-v2.md), [ai-workflows.md](ai-workflows.md), [pilot-plan.md](pilot-plan.md)와 현재 경계인 [architecture.md](architecture.md), [requirements.md](requirements.md), [sprint-00-report.md](sprint-00-report.md)를 따른다. 설치, 저장 프로필, API, 실제 JWW 읽기/쓰기가 이미 구현되었다는 의미가 아니다. 첫 사용은 로컬 읽기 전용이다.

## UX 원칙

- **바로 로컬에서 시작:** AI 공급자·키 등록 없이도 프로필 매핑, snapshot 검사, 검토와 기록을 시작할 수 있다. 네트워크를 켜라고 요구하지 않는다.
- **snapshot 범위 고지:** 사용자가 Jw_cad에서 외부변형을 실행한 순간에 제공된 선택 snapshot만 다룬다. 실시간 선택 동기화를 암시하지 않는다. 애드온은 자체 창/결과 목록을 가지며, Jw 내부 도킹 창·Jw 화면 확대/이동 제어를 약속하지 않는다. 애드온 내부에서 위치 확대/전체 맞춤을 제공할 수 있다.
- **숫자 설정을 먼저 확인:** 그룹 번호와 축척은 프로젝트마다 실제 표기/사용법을 사용자에게 확인한다. 표준 이름이나 객체 의미를 자동 추론하지 않는다.
- **AI 초안은 출처와 같이:** 지시문 원문 발췌를 나란히 보여주고, 대상이 모호하거나 값이 미정이면 개별 검토 작업으로 남긴다.
- **검사 coverage를 먼저:** 검사된 범위·항목, 제외·지원 안 됨·실패를 결과 수와 함께 보여준다. 미검사를 오류 없음으로 표시하지 않는다.

## 첫 사용 흐름

### 1. 시작 — 개인용 또는 사무소 관리자

환영 화면에서 작업 모드를 고른다. 새 사용자는 `일반 사용자`로 진입한다. 로컬 사용 경로는 첫 화면에서 곧바로 열리며 API 설정을 건너뛸 수 있다. `사무소 관리자`는 설정 잠금, 제공자 정책, 프로필 배포용 내보내기 준비를 본다. 이는 역할별 화면 제안이며 계정/권한 시스템이 구현되었다는 뜻은 아니다.

- **일반 사용자 기본 메뉴:** `검사 시작`, `수정 지시 정리`, `미해결/재검토`, `프로필 선택`.
- **관리자 고급 설정:** 실제 CAD 숫자 매핑, 프로필 버전, 허용된 provider/model, 비용·전송 정책, 키 상태.
- 사용자는 언제든 로컬 기능으로 돌아간다. AI 설정 오류가 검사를 막지 않는다.

### 2. 로컬 사무소 프로필 보정

마법사는 실제 파일/sample snapshot에서 관측한 `layerGroup` 숫자(예: 0–F)와 축척값을 표로 보여준다. 값이 관측되지 않았으면 채우지 않고 “아직 확인되지 않음”으로 둔다. 가져온 관측값은 읽기 전용으로 남긴다. 사용자가 의미를 보정하면 `사용자 지정값`을 별도 칸에 입력하고, 입력자·시각·프로필 revision·이유를 관측 출처와 분리 기록한다. 보정값이 원래 관측값을 덮어써서 관측 사실로 보이면 안 된다.

축척은 관측값 목록(예: 1/50, 1/100)이 보이면 관측값으로 보존한다. 다른 축척을 쓰려면 별도 사용자 지정값으로 등록하고, 분모·도면 단위·실제 길이 관계를 미설정이면 변환/작도 쓰기를 비활성화한다. 활성화 전에는 사용자가 실제 길이를 알고 있는 명시적 fixture(예: 알려진 기준 길이의 검증 도형)를 이용해 표시 길이·환산 결과가 맞는지 확인하고 그 fixture와 검토 결과를 프로필에 기록한다. 값 편집만으로 변환/쓰기를 허용하지 않는다. 검증 안 된 단위를 자동 환산하거나 가정을 고정하지 않는다. 텍스트 높이, 선형, 스타일 별칭, 알려진 예외도 선택적으로 매핑한다. 처음에는 프로필 복잡도를 줄여 그룹과 축척만 설정한다.

| 단계 | 사용자 행동 | 저장되는 초안 |
|---|---|---|
| 관측값 확인 | 현재 snapshot에서 받은 원 숫자 목록 확인 | 수정 불가한 관측값과 snapshot 식별자 |
| 회사 의미 입력 | 각 그룹 번호의 별칭/사용 목적을 사용자 지정으로 작성 | 출처가 관측과 분리된 매핑 revision |
| 적용 범위 확인 | 포함 그룹, 제외 그룹, 미설정 축척 선택 | 허용 검사 범위와 제외 이유 |
| 축척 검증 | 쓰기/환산을 요청하는 경우, 알려진 길이 fixture로 출력 결과 확인 | fixture·기준값·결과·검토자 |
| 미리보기 | 각 그룹/축척의 객체 건수 및 검사 가능 상태 확인 | 검사 전 coverage preview |
| 저장 | 이름과 프로필 revision 확정 | 로컬 프로필 v1; 추후 변경 이력 |

기존 파일의 패턴만으로 “이것이 회사 표준”이라고 학습/자동 확정하지 않는다. `이름/의미를 정하지 않고 로컬 검사만 시작`을 허용하되, 이 경우 관련 규칙은 지원 불가/미평가로 분리한다.

### 3. 선택 snapshot을 검사

사용자가 Jw_cad에서 검사할 도형을 선택하고 외부변형을 실행하면 애드온은 전달받은 snapshot의 새 ID와 해시를 표시한다. Jw 화면에서 현재 선택을 계속 읽는 것처럼 보이면 안 된다. 시작 화면에는 프로필명/revision, 관측 범위, 입력 버전, 선택 객체/지원 객체/미지원 객체 수를 표시한다. 대상 도면이 달라졌으면 새 외부변형 snapshot을 요청한다.

`검사 시작` 전에 1회 coverage preview를 보여준다. 기본 사용자는 “이 snapshot의 이 범위에서 실행”만 결정한다. 고급 사용자는 규칙 세트, 제외 그룹, 세부 엔진 버전을 확인한다. 검사 결과 창은 별도 애드온 창이며, `선택 객체로 Jw 화면 이동` 같은 아직 없는 기능은 제공하지 않는다. 애드온 자체의 확대/전체 맞춤은 결과 geometry에만 적용된다.

### 4. Coverage와 검사 결과 읽기

결과 상단에 발견 건수만 두지 않고 검사 coverage를 병렬로 보여준다. 결과를 사용자가 필터링해도 원래 실행 범위와 검사 상태를 잃지 않는다.

- **검사함:** 해당 rule version이 실행된 객체/그룹 수.
- **지원 안 됨:** parser/객체 타입이 지원하지 않아 판단하지 않은 수.
- **제외:** 프로필/사용자 설정에서 뺀 그룹·범위와 이유.
- **실패/중단:** 검사 중 오류나 취소로 판단하지 못한 범위.
- **발견 없음:** 검사한 rule의 조건에 해당하는 항목을 찾지 못함. “도면이 정상”이라는 승인 문구가 아니다.

판정 카드는 rule, 측정값·단위·허용값, 원본 위치/객체 후보, 적용 프로필·엔진 버전을 표시한다. 검토자는 발견/의도된 표현/보류 중 하나를 고른다. 쓰기 제안이 구현되기 전까지 이 흐름은 도형을 수정하지 않는다. “발견 없음”과 “검사하지 않음”의 시각적 색상 의존을 피하고 텍스트 상태도 늘 표시한다.

### 5. 지시문에서 revision task 초안 만들기

기본 사용자는 짧은 일본어 지시를 붙여 넣고 `지시 작업으로 나누기`를 선택한다. 실행 직전에 전송 범위 preview에는 원문, 선택한 문서/페이지/발췌, 민감정보 경고, provider, 모델, 입력/출력 token 한도와 요청 비용 상한(추정값), 데이터 보존/사용 정책 링크를 표시한다. 사용자 확인 전 호출하지 않는다.

응답은 각 task 옆에 **원문 출처 발췌**를 나란히 보여준다. 작업 유형은 수정/확인/질문으로 구분한다. `W-07`이 여러 위치를 가리키거나 단위가 불분명하면 대상을 자동 지정하지 않고 “대상 확인 필요”로 둔다. 지시문에 미정이라고 적힌 값은 빈 채 유지한다. 사용자가 항목별로 대상·요청값·완료 기준을 승인해야 정식 revision task가 된다. AI 초안의 생성은 도면 수정, 업무 완료, 신청 발행을 의미하지 않는다.

### 6. 미해결과 재검토를 별도로 인수

작업함은 상태를 분리한다: `미확정 초안`, `열림`, `작업 중`, `검토 대기`, `검토 완료`, `미해결/재검토 필요`, `취소/대체`. 스킵·모호·미지원·응답 오류는 검토 완료에 합치지 않는다. “지금 건너뛰기”는 현재 필터에서 숨길 뿐이며 별도 `미해결/재검토` 수와 목록을 유지한다.

재검토 카드는 마지막으로 연결된 source span, snapshot/file hash, 프로필 revision, rule version, 담당/검토자, 마지막 이유, 다음 행동을 보여준다. 새 snapshot과 이전 task가 확실히 매칭되면 “재검토 후보”를 제시한다. 객체 매칭이 없거나 다대일/일대다 후보면 해결 처리하지 않고 사용자가 연결한다. 검토 범위/프로필/규칙이 바뀐 제외·보류 항목도 다시 확인 큐로 돌아간다. 완료 기록에는 사람의 확인과 기계 evidence를 구분한다.

## AI BYOK와 정책 설정 (선택, 고급 설정)

공급자/API가 준비되지 않으면 AI 항목은 `미설정`으로 보여주되 검사의 완결된 대체 경로를 제공한다. 유효 provider는 제품이 검증한 목록에서 선택하게 한다. 임의 모델 문자열이나 사용자 ChatGPT 구독 접근을 암시하지 않는다.

| 설정 | 안내/검증 |
|---|---|
| 제공자 + API endpoint | 기본 공식 endpoint. proxy/사내 gateway는 관리자만 추가하고 TLS·인증을 별도 검증 |
| 모델 | provider에서 실제 확인한 모델만 선택. 기능 미지원이면 비활성/이유 표시 |
| API 키 | native OS의 보안 자격 증명 입력 dialog에서 수집하고 OS credential vault에 보관. renderer에는 전달·저장하지 않는다. UI에는 마스킹된 식별이나 “등록됨”만 표시 |
| 보관/훈련 정책 | 제품이 확인한 provider 공식 정책/계약 날짜와 link 표시. 불명확하면 전송 차단 또는 관리자 재량이 아니라 제품 정의 정책상 비활성 |
| 전송 정책 | 사용자가 선택한 지시문과 최소 후보 ID만. CAD 원시 geometry/전체 도면은 기본 전송 금지 |
| 예산/요청 제한 | task별 월/요청 한도. 사전 추정 및 실제 사용량이 provider에서 돌아오면 기록. 미제공 비용은 추정이라고 명시 |

앱이 통제하는 renderer, analytics, 오류 로그, 앱 crash report에는 평문이 기록되지 않게 한다. 키 취급이 필요한 작업은 native host의 보안 자격 증명 dialog로 제한하고, provider 호출을 위해 host에서만 해독한다. 사용자 log/export에 key 또는 전체 인증 header를 넣지 않는다. Windows clipboard history, OS crash dump, 제3자 진단 수집 등 앱 밖의 전역 저장 경로에 평문이 전혀 남지 않는다고 보장할 수는 없다. 구현·보안 검증 전에는 키 입력 화면을 내놓지 않는다. 이 파일은 설계 요구사항이지 현 구현이 보안 인증을 받았다는 뜻이 아니다.

## 오류·취소 동작

요청 중 상태에는 provider/model과 task, 현재 전송/응답 단계, 취소 버튼을 표시한다. 취소를 누르면 진행 상태가 명시적으로 취소로 바뀌고, 늦게 온 응답은 버린다. 이미 공급자에 도달한 요청은 취소 이후에도 처리되거나 과금될 수 있음을 알린다. 네트워크 오류, timeout, rate limit, 인증 오류, budget 초과, schema 불일치는 종류별 문구를 낸다. 사용자가 현재 프로젝트 정책에 따라 최초 payload 전송을 승인할 때 적용된 **같은 payload·같은 provider/model·같은 옵션·같은 receipt** 안에서는 미리 승인된 재시도 횟수와 비용 상한까지 제한적으로 자동 재시도할 수 있다. 승인 한도를 넘거나 provider/model/payload/옵션을 바꾸는 수동 재시도에는 새 receipt가 필요하다. 이를 별도의 불필요한 승인 단계로 반복하지 않는다.

네트워크가 끊기면 “이번 AI 작업이 완료되지 않음”을 표시한다. 검사/로컬 task 결과가 있으면 그대로 유지하되 AI task를 빈 성공으로 만들지 않는다. 다른 provider 전환이나 다른 모델 호출은 하지 않는다. 사용자가 원하면 **AI 결과가 아닌 로컬 템플릿**(예: 원문 인용만 있는 빈 작업 목록)을 명확한 표시와 함께 만들 수 있다. 같은 승인 payload의 제한 내 자동 재시도 외에, 설정/입력을 바꾼 재시도는 새 receipt로 시작한다. 잘못된 JSON/schema 응답은 보여주지 않고, 보내지 않은 콘텐츠를 모델이 읽은 것처럼 인용하지 않는다.

| 비용/전송 | 送信内容と費用を確認 | Review payload and cost |
| 인증 오류 | APIキーを確認してください。キーは更新されませんでした。 | Check the API key. It was not changed. |
| 취소 | AI処理をキャンセルしました。送信済みの場合、提供元での処理や課金が続くことがあります。下書きは未確定です。 | AI request cancelled. If already sent, the provider may continue processing and charging. The draft is not confirmed. |
| 오프라인 | ネットワークに接続できません。AI結果は作成されていません。ローカルテンプレートを使用できます。 | Network unavailable. No AI result was created. A local template is available. |
| 상한 초과 | 予算上限に達したため送信していません。 | Request not sent: budget limit reached. |
| schema 오류 | 回答形式を確認できませんでした。内容をタスクに追加していません。 | Response format could not be verified. No tasks were added. |

## Release checks for this UX (proposed)

- 일본어 UI로 API key를 설정하지 않은 Windows 사용자도 프로필 draft→snapshot coverage preview→로컬 검사→판단 저장을 끝낸다.
- 실제 group/scales 값을 읽을 수 있는지, 잘못된 사용자 매핑을 재편집할 수 있는지, mapping 변경이 기존 검토를 다시 확인 상태로 전환하는지 평가한다.
- selection은 외부변형 실행 때 전달된 일회성 snapshot으로 표시되고, 새 데이터는 사용자가 다시 외부변형을 실행해 전달해야 갱신된다.
- 검사 건수가 낮더라도 미지원/제외/실패 범위가 coverage에 남는다. 재검토/미해결은 별도 탭·카운터로 추적 가능하다.
- AI task 전에는 실제 payload preview·비용 제한·정책 정보가 보이고 확인/취소가 가능하다. 오류에서 조용한 네트워크 전환이나 완료 처리가 없다.
- secret scanner뿐 아니라 실제 Windows renderer/log/crash 경로 확인으로 API 키 노출이 없는지 검증한다. 이 검증 전에는 BYOK를 pilot에 켜지 않는다.
- 모든 검사는 설치된 연동/저장 기술이 확정된 뒤 별도 sprint acceptance로 추가한다. 이 문서 작성 자체가 구현 완료나 자동 승인 기준 통과를 뜻하지 않는다.
