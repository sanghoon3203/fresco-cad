# I2A — 사무소 규칙과 로컬 검토 기록 계약

이 단계는 읽기 전용 캡처 리뷰에 사무소 프로필과 검토 기록을 추가한다. 실제 CAD 수정, AI API, 도면 내용 저장, 여러 사용자 공동 편집은 범위 밖이다. Windows 배포 제품의 SQLite 저장소를 대신 완성한 것으로 간주하지 않는다.

## 사용자 작업

1. 기존 방식으로 JWC_TEMP를 선택하고 문자 코드·단위·그룹을 확인한다. metadata를 선택했다면 먼저 페어 검증을 통과해야 한다.
2. 사무소 규칙에서 짧은 선 기준(mm), 가까운 끝점 기준(mm), 허용 레이어를 편집하고 명시적으로 저장한다. 저장 성공 후 새 프로필 버전으로 다시 검사한다.
3. 검출 항목을 선택해 검토 중 / 검토 제외 / 재확인 상태와 메모를 저장한다. 검토 제외에는 이유가 필요하며 항목을 화면에서 삭제하거나 수정 완료로 표시하지 않는다.
4. 브라우저를 다시 열면 프로필과 기록은 남아 있다. 도면 파일은 다시 선택하고 단위·그룹을 확인해야 한다. 동일 검사 문맥의 기록만 다시 연결한다.
5. 현재 검사와 검토 상태를 JSON 또는 CSV 텍스트로 확인하고 복사할 수 있다. 저장된 workspace와 직전 정상 백업도 별도 JSON으로 확인한다.

## 모듈 경계

`core/engine.mjs`는 기존 기하 검사를 유지한다. `review/store.mjs`는 검토 데이터의 검증·문맥 식별·저장소 어댑터를 담당한다. `review/export.mjs`는 현재 문맥에 속하는 검토 기록만 CSV로 변환한다. UI는 이 모듈을 호출하고 일영 문구로 결과를 표시한다.

사무소 프로필은 실제 가져오기에만 적용한다. 합성 데모의 수정·미리보기 계약은 기존 기본 프로필을 유지한다. 프로필이 아직 없으면 가져오기에서 관측한 레이어를 허용하는 기존 기본 규칙을 사용하며, 이를 회사 표준 검증으로 설명하지 않는다.

## 동일 문맥 판단

다음 값을 검증하고 정규화한 뒤 SHA-256으로 문맥 키를 만든다.

- 원본 캡처 바이트의 SHA-256
- 선택 문자 코드, 좌표 해석(model-mm / paper-mm), 그룹 ID
- 프로필 ID·버전·허용 레이어 목록·수치 기준 전체
- 검사 엔진 계약 버전 `line-checker-v1`

파일 이름, 일시, 레이어의 건축적 추정 의미는 식별 기준이 아니다. 소스나 규칙이 달라지면 새 문맥이다. 기존 결정을 다른 도면에 자동으로 이월하거나, 새 선택에 보이지 않는 문제를 해결된 것으로 처리하지 않는다. 엔진의 검출 결과나 ID 구성 규칙을 바꾸면 문맥의 엔진 계약 버전도 갱신해야 한다.

## 저장과 실패

현재 시제품은 같은 브라우저 origin의 `localStorage`를 사용한다. 기록에는 프로필, 문맥 키, 이슈 ID, 최근 검토 상태·메모·기록 일시가 들어간다. 도면 바이트, 원본 경로, API 키는 저장하지 않는다. 메모에 사용자가 입력한 내용은 로컬 기록에 포함되므로 업무 기록으로 다룬다.

문맥·이슈별 최신 판단을 보관하는 구조이며, 모든 과거 수정 이벤트를 남기는 감사 로그는 아니다. 제한은 500개 기록, 메모 2,000자, 저장 JSON 2 MiB다. 상한·지원하지 않는 형식·손상된 JSON을 무시하고 초기화하지 않는다. 저장 실패 시 성공 표시를 하지 않고, 현재 검사 자체는 계속 사용할 수 있어야 한다.

저장할 때 기존 정상본을 `.backup` 키로 먼저 보관하고 새 revision을 기록한다. 오래된 revision의 저장 요청은 거부한다. 이 확인은 브라우저 탭 간 원자적 transaction이 아니므로, 현재 시제품은 **한 탭에서 순차 사용**한다. 백업은 직전 정상 상태이며 전체 이력이 아니다. 브라우저 저장소 삭제·다른 브라우저·다른 포트에는 자동 승계되지 않는다.

손상된 primary를 자동 덮어쓰지 않는다. 백업 JSON을 열어 보존할 수 있지만, UI를 통한 파일 복원과 migration은 후속 단계다. 서버는 저장 내용을 HTTP로 제공하지 않고 정적 코드 파일만 허용한다.

## CSV 계약

`reviewCsv(issues, reviews, contextKey)`는 단일 문맥의 CSV 텍스트를 반환한다. 각 행에 문맥 키를 포함하고, 다른 문맥의 기록이 섞이면 거부한다. 미검토 항목도 `unreviewed`로 포함한다. 제외는 `excluded`이며 수정 완료 상태는 없다.

일본어를 위한 UTF-8 BOM, CRLF 행 구분, 따옴표·개행 escaping을 사용한다. 텍스트가 공백 뒤 `=`, `+`, `-`, `@`로 시작하거나 선행 탭·개행을 포함하면 작은따옴표를 앞에 넣어 표계산 수식 실행을 방지한다. 좌표 숫자는 수치로 유지한다. 실제 Excel에서의 파일 저장·재열기 검증은 별도 게이트다.
