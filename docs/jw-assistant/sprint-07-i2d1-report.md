# Sprint 07 — 빠른 프로젝트 파일 프로토타입

2026-09-28. Sprint 06의 복구 기능 다음으로 **한 도면을 파일로 보관하고 다시 여는 사용 흐름**을 구현했다. I2D 전체 완료가 아닌 I2D1 휴대 가능한 파일 세션 완료다.

## 구현

- 원본 캡처, 선택한 인코딩/단위/그룹, 검토 기록, 사무소 규칙, 레이어 대응과 현장 메모를 `.jwproject.json`에 저장.
- 즉시 시험 가능한 합성 샘플과 기존 캡처에서 프로젝트 생성.
- 파일 검증 → 내용 미리보기 → 명시적 열기. 원본 SHA-256/선택 메타데이터를 검증하고 도면 검사를 재실행.
- 기존 브라우저 기록과 별도 메모리 세션. 프로젝트 종료 후 이전 브라우저 작업으로 복귀.
- 입력 초안·파일 미저장 변경의 전환/종료 방지, 명시적 폐기, 다운로드 확인. 저장 확인 후 추가 변경이 생기면 다시 파일 저장 필요.
- Jev의 공식 기능/한계를 조사하고 [도입 판단](research/jev-assessment-2026-09-28.md)을 갱신. AI는 연결하지 않음.

## 실행한 검증

`node --test tests/*.test.mjs`: **74/74 통과** (기존 67 + 프로젝트 파일 7).

새 테스트: 기록/바이트 round-trip, 메모리 저장소 분리, 미래·손상·초과 크기 파일 거부, 변조 해시/base64 거부, Shift_JIS 바이트 보존, 메타데이터 일치/불일치, 조건 변경 시 이전 문맥 유지.

별도 포트 54727의 브라우저에서:

- 샘플 미리보기와 열기, 단위/그룹/소스 변경 잠금.
- 입력 중 메모를 저장하지 않은 다운로드 거부.
- 검토 메모와 현장 위치 메모 저장, 파일 미저장 표시, 미저장 종료 거부.
- 실제 다운로드 파일(2,790 bytes)에 두 메모가 포함됨을 확인.
- 다운로드 확인 후 종료, 기존 브라우저 검토 기록이 빈 상태 그대로임을 확인.
- 다운로드 파일을 파일 선택기로 재열어 두 메모 복원 확인; 브라우저 오류 로그 없음.
- 일반 합성 TXT를 읽고 단위/그룹을 확정한 후 새 프로젝트 생성 확인.

실도면을 새로 검사하거나 Jw를 실행하지 않았다. 예제는 저장소의 합성 입력만 사용했으며 OneDrive 개인 자료는 추가로 복사/게시하지 않았다.

## 다음 게이트

1. 파일 다운로드를 직접 덮어쓰기/원자 저장으로 표현하지 않는다. I2D2: host 파일 저장, 이전 정상본, 쓰기 중 실패/중단 복구.
2. 실제 Jw 호환성·설치/제거·사무소 파일럿과 기존 Undo/Redo 게이트는 계속 미완료.
3. AI는 합성 평가셋과 FakeProvider부터 진행. Jev를 치수 계산/자동 작도 엔진으로 사용하지 않는다.

사용 순서와 정확한 파일 계약은 [프로젝트 파일](project-file.md)을 참조한다.
