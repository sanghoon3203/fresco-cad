상태: 공개자료 조사와 사용자 조건을 반영한 개발 기준. 고객 인터뷰·실제 도면 쓰기·API 품질·출시 검증은 아직 완료되지 않았다. 변경 이유와 업무별 근거는 [제품 계획 v0.2](product-plan-v2.md), [조사 근거](research/evidence-ledger.md)를 따른다.

## 1. 확정한 제품 방향

일본의 **목조 단독주택을 다루는 소규모 설계사무소**를 위한 Windows 애드온을 먼저 만든다. 사용자는 Jw_cad에서 설계를 계속하고, 도구는 출도 전 점검과 정리 작업을 줄인다. 기존 Fresco CAD 전체 교체 제품과 별도 모듈로 개발한다.

- 대상 OS: 우선 Windows 11 x64. Windows 10은 고객 수요와 실제 시험을 거친 별도 호환 대상. macOS·Linux·ARM64는 이번 범위 밖이다.
- Jw_cad: 사용자는 최신판에서 실기 테스트 가능하다고 확인했다. 조사 기준 최신 `10.03.6`을 첫 시험 대상으로 고정한다. 설치된 실행파일 버전도 별도로 기록한다. 자동으로 미래 버전을 지원한다고 간주하지 않는다.
- 언어: 설정에서 Japanese / English 전환, 기본 일본어, 즉시 반영 및 설정 보존. 설계 원문·도면 문자를 UI 언어에 맞춰 자동 번역하지 않는다.
- 개인정보: 검사·기하·저장은 로컬. 프로젝트별 허용 범위가 설정된 경우만 최소 정보로 클라우드 설명/추천을 요청한다. 기본은 외부 전송 없음.
- AI는 해석·설명·후보 추천을 담당한다. 좌표·허용오차·수량·수정 실행은 검증 가능한 프로그램이 담당한다.
- 모든 도면 변경은 수정안 미리보기와 사용자 승인을 거친다. 구조·법규·설계 의도 판단은 설계자의 책임과 판단 영역으로 남긴다.

근거: [Jw_cad 공식 다운로드](https://www.jwcad.net/download.htm), [공식 변경이력](https://www.jwcad.net/versioninfo.htm). 재확인일 2026-09-23.

## 2. 지금 만드는 MVP

가칭 **Fresco Jw Assistant — 도면 점검과 출도 검토 기록**.

첫 수직 기능은 다음과 같다.

> Jw_cad에서 범위 선택 → 외부변형으로 선택 데이터 전달 → 로컬 검사와 검사 범위 표시 → 설계자의 판단 기록 → Jw에서 수동 수정 → 새 snapshot 재검사 → 검토 기록 보존.

첫 파일럿은 읽기 전용이다. 다음 쓰기 릴리스에서 명확한 정리 항목의 preview → 승인 → 지원이 검증된 버전에서 한 번 반환을 추가한다. 읽기 전용 제품의 출시를 쓰기 또는 AI 연결 완료와 묶지 않는다.

첫 고객 가치는 “확인해야 할 곳을 빠르게 찾고 검토 기록을 남긴다”이다. 정확 중복선 삭제만으로 장기 유료 가치를 가정하지 않는다. 다음 유료 차별점은 회사 규칙, 발행 전 점검 결과, 이전 점검 대비 변경, 제외 사유와 변경대장이다.

**이번 Sprint 0 산출물은 합성 데이터 실행 시제품과 실데이터 수집 도구다. 설치형 Jw 애드온 완성이나 JWW 호환 완료를 의미하지 않는다.**

## 3. 작업별 가치 비교

공개자료로 작업별 Jw 평균시간·절감률을 확인하지 못했으므로 v0.1의 수치 범위 가설은 제거했다. 발생 계기, 측정 단위, 자동화 가능성, AI 필요성, 난도·위험·책임·상업 가치는 [제품 계획의 단계별 비교표](product-plan-v2.md#4-업무-단계별-기회와-책임)에 통합한다. 상대 평가는 제품 책임자의 가설이며 실측 순위가 아니다.

중소 사무소의 역할 겸임·인수인계·공유 폴더 운영은 고객군별로 관찰한다. 실제 시간과 유료 수요는 [파일럿 계획](pilot-plan.md)에 따라 평가한다. 기존 Jw 기능과 외부변형이 수행하는 정리·비교·측정을 기준 대안으로 포함한다.

텍스트 겹침·문자 크기·치수 누락은 이름만 붙인 가짜 검사를 만들지 않는다. 문자 메트릭·일본어 폰트·회전/축척 및 연관 치수의 의미가 확인된 뒤 개별 규칙으로 추가한다. 전체 파일 검사·도면 세트 분석은 선택 범위 외부변형만으로 완료했다고 표시할 수 없다.

## 5. 첫 MVP에서 제외하는 기능

- 구조 부재 결정, 법규 적합 결론, 자동 확인申請, 내력벽·梁 치수 계산.
- 평면→입면/단면의 자동 완성, 자연어만으로 벽/창문 삽입.
- 모든 JWW 버전 직접 읽기/쓰기, 손실 없는 전체 도면 왕복 약속.
- Jw 내부에 실제 dock되는 채팅창, 실시간 selection event, 임의 zoom/pan 제어.
- 사용자 모르게 자동 수정·클라우드 업로드·도면 학습·백그라운드 전체 디스크 검색.

## 7. 상업 검증 계획

제품 형태는 **로컬 앱 + 사무소 단위 라이선스**를 우선 가설로 둔다. 클라우드 AI 비용은 선택 옵션으로 분리한다. 유료 도입 전 3~5개 사무소에서 각 2회 이상 출도 업무를 관찰한다. 샘플 수가 작으므로 시장 대표성이나 보장 ROI로 표현하지 않는다.

측정: 수동 점검시간, 도구 실행+사람 검토+수정시간, 규칙별 참/거짓 양성, 뒤늦게 발견된 누락, 수정 취소율, 출도 후 재작업시간. 같은 도면을 두 번 보는 학습효과를 줄이기 위해 과제·실행 순서를 교차 배정한다. 설계 난도가 다른 프로젝트끼리 단순 비교하지 않는다.

파일럿 목표: 출도 점검 중앙시간 30% 감소, 경고형 규칙 정밀도 90% 이상, 명확한 중복/0길이 합성 골든 100%, 무고지 변경 0건. AI 추출 task precision/recall 각각 95%를 잠정 목표로 두고 단위·숫자 오류를 별도 보고한다. 고객과 함께 라벨한 실도면 기준 recall도 별도로 계산한다. 시제품 unit test 통과를 이 실무 수치 달성으로 대체하지 않는다. 표본·평가 방법·기각 조건은 [파일럿 계획](pilot-plan.md)에 명시한다.

가격은 아직 정하지 않는다. 검증된 절감시간×사무소 인건비에서 검토·교육·오탐 비용을 빼 월간 가치를 계산하고 가격별 지속 사용 의향을 조사한다. 도면 파일 해시도 외부 전송 동의 없이 분석 서버로 보내지 않는다.

## 8. 남은 외부 입력

사용자는 대상 고객, 로컬/클라우드 정책, 최신 Jw 사용과 실기 가능 여부를 답변했다. 지금 추가 질문 없이 개발 가능한 상태다. 이후 실제 도면 코퍼스와 회사 레이어 규칙을 받아 호환 게이트를 검증한다. JEV 공급자·정확한 API가 없으므로 구현 상태는 `unconfigured`이며, 성능 향상을 주장하지 않는다.
