# I2C — 백업 복원과 손상 원본 보존

2026-09-28. 사무소 검토와 현장 메모는 서로 독립된 저장 영역이다. 백업 복원은 해당 영역 전체를 교체하며 병합하지 않는다. 원본 CAD 파일에는 쓰지 않는다.

## 사용 흐름

1. 사무소 규칙·검토 판단은 설정의 **事務所ルール・検討記録の復元 / Restore office rules and review decisions**, 레이어 분류·현장 카드는 **分類・現場メモのバックアップ復元 / Restore mapping and site notes**를 연다.
2. 현재 저장본을 JSON 파일로 내려받을 수 있다. 손상된 저장본도 파싱하지 않고 내보낸다. 과거에 격리한 원본은 별도 다운로드한다.
3. 직전 백업을 불러오거나 JSON 파일/텍스트를 입력하고 검증한다. 가져올 데이터는 2 MiB 이하다. 사무소 백업은 review v1, 현장 백업은 field v1/v2만 받는다. 서로 다른 종류의 백업을 바꿔 넣으면 거부한다.
4. 현재/복원 후 건수와 프로필 유무를 비교하고 펼침 영역에서 교체할 전체 데이터를 확인한다. 정상 저장본을 못 읽으면 원문 보관 후 복구한다는 안내를 표시한다.
5. 미저장 입력을 저장하거나 명시적으로 되돌린 다음 **확인한 백업으로 교체**를 누른다. 복원 성공 후 동일한 도면과 검사 조건을 다시 확인한다. 파일명만으로 다른 도면에 기록을 연결하지 않는다.

이 작업은 자동저장이나 영구 파일 작업 공간이 아니다. 브라우저/포트가 달라지면 저장소도 달라지므로 다운로드한 백업이 필요하다.

## 저장 계약

공통 구현은 `storage/local-store.mjs`의 `createJsonStore`다. 기존 사무소와 현장 데이터의 키·schema·일반 저장 계약은 유지한다.

- `prepareRestore(raw)`: incoming을 엄격 검증하고 필요하면 현장 v1을 v2로 변환한다. 읽기만 하며 저장하지 않는다. 현재 raw 문자열과 적용할 데이터를 고정하고, 외부에서 수정할 수 없는 미리보기를 반환한다.
- `applyRestore(preview)`: 같은 store 인스턴스가 만든 1회용 미리보기만 받는다. 직전 검증 시점의 raw와 현재 값이 다르면 revision이 같아도 거부한다. 실패 후에도 다시 검증해야 한다.
- 정상 primary: 원래 문자열을 `.backup`에 먼저 저장한 뒤 교체한다. revision은 현재 값 + 1이며 가져온 백업의 revision을 신뢰하지 않는다.
- 없거나 손상된 primary: 복원 revision은 1부터 시작한다. 읽을 수 없는 기존 원문은 `.quarantine`에 `{savedAt, raw}`로 보존한다. 기존 정상 `.backup`은 유지한다. 지원하지 않는 미래 schema도 자동 삭제하지 않고 같은 복구 경로로 보존한다.
- 격리 보관은 중복 원문을 합치고 최대 5건, 직렬화된 JSON 8 MiB로 제한한다. 보관소 자체의 손상·상한·실제 브라우저 용량 부족은 primary 교체를 차단한다. 자동으로 오래된 원본을 지우지 않는다.
- 보관 성공 후 primary 기록이 실패해도 기존 primary와 정상 backup은 유지되며 격리 사본이 남을 수 있다. 재시도는 같은 원문을 중복 추가하지 않는다.
- 일반 `save`는 여전히 손상된 primary를 거부한다. 복구는 명시적 preview/apply 경로만 사용한다.

브라우저 저장 용량은 환경에 따라 더 작을 수 있다. 8 MiB는 보장 용량이 아니다. 격리 보관소가 차거나 손상되면 화면에서 원본을 다운로드해 보존할 수 있지만, 보관소 정리/외부 파일을 이용한 강제 복구 UI는 아직 없다.

## 입력 보호와 한계

사무소 복원은 현재 사무소 규칙·검토 입력과 현장 초안이 있으면 차단한다. 현장 복원은 미저장 분류/카드 초안이 있으면 차단한다. JSON 내용 수정, 일반 저장, 현장 초안 수정은 해당 미리보기를 무효화한다. 저장 후 화면 갱신에 실패하면 저장 실패와 구분하여 재열기를 안내한다.

사무소 검토 입력의 **모든 문맥 전환에 대한 초안 보존**은 구현하지 않았다. 현재 입력의 복원 차단과 페이지 이탈 보호를 제공할 뿐이며, 다른 검사항목/도면으로 바꾸기 전에 저장해야 한다. 현장 초안은 기존의 문맥별 보존 계약을 유지한다.

`localStorage`는 여러 탭에 걸친 원자적 compare-and-swap을 제공하지 않는다. 원문 재확인을 해도 마지막 확인과 기록 사이의 경쟁은 남는다. **한 탭에서 순차 사용**하며 공동 편집·다중 탭 transaction·충돌 없는 동시 복구를 보장하지 않는다. 브라우저 저장소 자체 삭제, 강제 종료 중 미저장 초안, CAD 원본은 이 기능으로 복구할 수 없다.
