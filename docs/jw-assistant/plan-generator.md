# 평면도 생성기 (Jw_cad 1/50 평면상세도) — 규칙 학습 · 생성 · 자기평가 루프

2026-10-01~02. 구현: `addons/jw-assistant/generator/` (`spec.mjs`, `model.mjs`, `geometry.mjs`, `symbols.mjs`, `draw-plan.mjs`, `evaluate.mjs`, `header-template.json`, `plan-spec.md`, `examples/*.json`), CLI `tools/generate-plan.mjs`, 테스트 `tests/generator.test.mjs`, 규칙 `knowledge/office-drafting-rules.json` (`measured`, `module`, `evaluation`).
출력(추적 안 함): `outputs/generated-plans/<plan>/vN.{jww,png,json}`.
연습 데이터(住宅A)는 읽기 전용으로 측정에만 썼고, 고객명·주소·회사·로고·표제란은 어떤 파일에도 옮기지 않았다. 생성 도면의 헤더는 연습 도면의 펜/선종/문자종/SXF 표 같은 **환경 설정 수치만** `header-template.json`에 담고(메모·레이어명·뷰 위치 제외), 표제란은 중립 문구로 새로 그린다.

## 2. 스펙 언어
`generator/plan-spec.md` 참조. 그리드(배열 또는 `{pitch,count}`), 직교 외벽 폴리곤(L형 가능), 내벽 세그먼트, 개구부 `{type, at(벽심 위 중심), width(기둥심 스팬), hinge, swing(N/S/E/W), slide}`, 실 `{name, at, kind, rect, doma}`, 설비/가구 `{type, at(중심), rotation}`. `validateSpec`이 구조 오류(비직교, 정션 관통, 벽 밖 개구 등)와 **尺モジュール 위반(455 격자 밖 구조 = 오류, 개구부 = 경고)** 을 돌려준다. JSON Schema = `PLAN_SPEC_SCHEMA`.

## 3. 생성기 (`drawPlan`)
- `createJww()` + 헤더 템플릿으로 **빈 문서에서** 시작, 그룹1 축척 50·그룹0 축척 1, 레이어명 규칙대로(8 ハッチ, B 色塗, D 文字, E 寸法, F 補助線).
- 벽면선 = 벽체(외벽 띠 −185..+65 ∪ 내벽 사각형) 합집합의 경계를 셀 그리드로 추출 → 모서리·T접합이 자동으로 깨끗함. 개구부는 잘라낸 뒤 문설주 경계만 버림.
- 외벽 부속선은 오프셋 폴리곤(마이터) 위에 그리고 개구/기둥 구간을 빼서 끊음. 단열·해치는 띠로 클리핑.
- 치수: (오프모듈 개구가 있을 때만) 개구 위치 단 / 455 배수 그리드 단 / 전체 — 최대 3단, 실점, 인출선. 태그는 예측 인출선과 다른 태그를 피해 배치. 중정(L형)의 후퇴 면은 인출선을 건물 외곽까지만.
- 모든 출력은 코덱 재인코딩 바이트 동일, JwwHelper DLL(`readJww`)로 다시 열어 엔티티 수 일치 확인.

## 4. 평가기 (`evaluatePlan`, 결정적·수치)
제도 점검(JWW를 다시 디코드): layer-role-purity, pen-per-layer, thick-faces-on-walls(벽 양면 100mm 샘플), wall-closure(면선 끝점 차수), openings-cut-walls, insulation-exterior-only, room-labels-inside-rooms(+면적 값), dimension-sum-equals-overall(각 치수선 값=점 간격, 합=길이), text-style-sizes, furniture-dashed, renders-without-overlap(문자 간·벽·설비·문 호·치수선 교차), columns-at-structure, grid-bubbles, fits-sheet, **grid-module**, **dimension-module**.
계획 점검(건축사 관점): room-sizes(침실 ≥4.5帖·짧은 변 2.2m, LDK ≥10帖…), room-module, corridor-width(≥780), circulation-ratio(≤12%), door-swing-clear, door-approach-clear(문 앞 600, UB 입구가 욕조 쪽이면 오류), sliding-door-pocket, wet-core-grouped, rooms-reachable(현관에서 문/개구 그래프), habitable-rooms-have-windows, entrance-doma, items-fit-rooms, items-no-clash(주방 통로 ≥800, 침대 머리-창).
점수 = 0.6·제도 + 0.4·계획(가중 통과율) − 오류 2점씩(최대 20).

## 6. 남은 한계
- 평가기 만점 ≠ 완벽한 설계: 채광 면적비, 수납량, 동선 길이, 구조(내력벽 량·4분할), 단열 성능, 법규(건폐율 등)는 미점검.
- 계단·2층, 경사/곡선 벽, 비직교 외형, 출창·FIX창·여닫이창·折れ戸, 설비 기호(감지기·환기·ガラリ), 筋交い, 창 3단 태그(제품 호칭·상단 높이)는 미구현.
- 치수는 선+실점+문자로 그림(CDataSunpou 미사용) → Jw_cad에서 치수 객체로 편집 불가.
- 실 구분은 벽심 셀 기반: 오픈 플랜은 `rect`로 나눠야 하고, 문 호/의자 등은 단순화한 발자국으로 판정.
- 렌더러 기준 시각 검증만 수행(Jw_cad 본체 화면 확인은 미실시). 펜 112(SXF) 해치는 우리 렌더러에서 굵게 보임(연습 도면도 동일).
