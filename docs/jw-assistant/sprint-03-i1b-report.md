# I1B スプリント報告 — キャプチャ検証と手動セッション分離

作成日: 2026-09-25 JST。判定: **このスプリントの実装・ローカル検証は完了。I1 の実機互換性ゲート全体と製品配布の承認は未完了。**

Jw の診断キャプチャと `metadata.json` を組み合わせ、取り違え・不完全な出力を検出してから線の検査へ進む機能を追加した。Jw の一時ファイルの保存先を手動で分ける準備スクリプトも追加した。これは実際の業務図面を変更する機能ではない。

## 実装したもの

| 項目 | 動作と限界 |
|---|---|
| セッション準備 | 呼び出すたびに GUID フォルダーを作成。SJIS BAT と helper のみをコピーし SHA-256 を照合。Jw のウィンドウとの対応付けは手動 |
| パス検査 | インストール先、相対・ドライブ相対・デバイスパス、既存の出力先 reparse point を拒否。既存ディレクトリを上書き・削除しない |
| 完了情報の公開 | 読み取り専用で取得し、コピーとハッシュを確認後に pending metadata を最終名へ rename。先頭 `hq` がなければ出力前に拒否 |
| ペア検証 | 最大 8 MiB のキャプチャと 64 KiB の metadata をブラウザー内で検証。完了マーカー・長さ・SHA-256・UTC 日時形式・実際の先頭行を確認 |
| UI | 任意の metadata 選択、検証結果・記録時刻・復旧案内を日英で表示。読み込み中・失敗時は検査とレポート出力を停止 |
| 生データへの復帰 | metadata を明示的に外した場合だけ未検証の読み込みへ復帰。単位・文字コードの変更では検証を迂回できない |
| レポート | 一致結果または raw-unverified を記録。metadata 内のファイルパスと生の本文は出力しない |

ハッシュ一致は、選択した二つのファイルの整合性を示す。発行者、Jw ウィンドウ、原図、取得時刻の真正性は保証しない。画面とレポートも `sourceAuthentication: unverified` と明示する。文字コードのヒントから単位や codec を自動決定しない。

## 並列作業

- GPT-6 Sol: セッション準備・Windows パス検査・回帰試験。
- GPT-6 Sol: ブラウザー用ペア検証モジュール・契約・拒否ケース試験。
- GPT-6 Luna: 日英 UI、metadata 選択、失敗時の案内と状態制御。
- プロジェクト責任者: producer の完了マーカー公開、統合レビュー、実機の文字コード調査、ブラウザー実動作確認、報告。

統合レビューで、容量超過などで metadata のバイト列が未取得のとき、設定変更から生データとして再開できる不具合を発見して修正した。metadata の選択状態を判定に使い、読み込み待ち・失敗を解除するには再選択または明示的な取り外しを必要とする。

## Jw 10.3.6 の追加観測

既存の Computer Use スキルを使い、診断用の無題ウィンドウで外部変形のファイル選択画面を確認した。バージョンは前回確認済みの `10.3.6.0`。今回の画面確認用の線は手描きであり、寸法校正には使っていない。

| 実験用 BAT | 選択画面の観測 |
|---|---|
| UTF-8、BOM なし、先頭に日本語 REM コメント | **S-JIS** と表示。日本語が文字化け |
| 既存 UTF8 BAT の内容に UTF-8 BOM を付加 | **UTF-8** と表示 |

両候補は選択画面での判定のみで、外部変形として実行していない。BOM は Windows の BAT 実行に影響し得るため、実行成功・日本語の出力・原図保存・戻り値までを確認する前に正式採用しない。今回の標準 staging は検証済みの SJIS のみ。選択画面を Escape で閉じ、診断用の線が表示された状態に戻した。

実験コピーは `C:\Users\Public\Fresco-I1B-20260925` に置いた。SHA-256 は以下。

- `UTF8_PROBE.bat`: `c4f99a16b25d02513b2c9b86b31e9ba3a7221eab52aac098a7e6f687e3bcba9b`
- `UTF8_BOM_PROBE.bat`: `dbd7b1c525f59e3e3bf1223c41411208f1b43bb6a37da604d5374ba9e23a05ad`

[Jw 公式バージョン情報](https://www.jwcad.net/versioninfo.htm)の 10.01.2 は BAT と外部変形データの文字コードの関係を説明している。BOM があらゆる環境で必要十分であるという一般化は、今回の単一環境観測からは行わない。

## 残る実機ゲート

1. 別 wrapper ディレクトリを二つの実 Jw ウィンドウで使う試験。現状はフォルダー作成・分離の検査まで。同じ wrapper の同時使用は引き続き禁止する運用。
2. UTF-8 BAT の実行互換性と、日本語データを含む出力の完全一致。
3. 複数グループ・混合縮尺・回転・実機 cancel/failure・保存ファイル不変性。
4. Native Undo/Redo と書き戻し。今回の読み取り専用機能の合格から書き込みを許可しない。
5. 事務所での操作観察、実プロジェクトの誤検出率・時間削減・支払い意思。事業性の実測値はまだ得られていない。

## 次段階 I2 の着手単位

| チケット | 追加する動作 | 合格条件 |
|---|---|---|
| I2-01 | バージョン付き事務所検査プロファイル。許容レイヤー・短線・隙間しきい値 | 単位・値域を検証し、変更時は再検査。現在の数値レイヤーから会社規則を推定しない |
| I2-02 | 検討中・対象外・要再確認と理由の記録 | 同じ capture hash・ルール版だけに結びつける。別キャプチャで自動的に「修正済み」にしない |
| I2-03 | ローカル保存・再開・JSON バックアップと CSV 出力 | 壊れた保存データを拒否し、上書き前の復旧経路を提供。日本語と表計算式注入を検証 |
| I2-04 | 検査設定と詳細の表示整理 | 頻用操作と描画を優先。狭いパネルでも設定のために結果を見失わず、日英・キーボードで完了できる |
| I2-05 | 読み取り専用の試用手順と実機残件 | インストール・削除・復旧を一般ユーザーで確認し、未通過環境には配布しない |

I2 は現在の読み取り専用境界を維持して進められる。API/BYOK の最初の対象は後続 I3 の修正指示抽出であり、FakeProvider と送信範囲・予算・評価を先に実装する。JEV は候補順位付けの交換可能な adapter として保留し、座標計算や規則の正否判定は deterministic engine に残す。
