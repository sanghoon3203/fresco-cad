# Fresco JWW — 파일 편집 중심 개발 계획 v0.3

2026-09-29. 사용자가 JWW → JSON → 수정 → JWW 방향으로 진행하도록 결정했다. 이 문서는 v0.2의 개발 순서와 MVP 범위를 대체한다. 구현 완료 보고가 아니다.

현재 구현: [JWW JSON 편집 CLI와 실파일 검증](jww-pipeline.md). 일반 선 이동·새 파일 출력·native 재파싱까지 구현했다. Jw_cad GUI 재개방, UI 연결, 자연어 편집은 남아 있다.

추가 구현: [블록 구조 IR v2와 건축 스킬 프레임워크](architecture-skills.md). 블록 정의·배치별 좌표 변환을 추출하고 건축 스킬 5종의 선택 문맥 생성·결과 검증기를 연결했다. 다음 통합 작업은 Studio에서 이 문맥으로 AI를 호출하고 편집 미리보기·새 파일 저장까지 잇는 것이다.

## 제품 방향

JWW 파일을 직접 열어 구조화하고, 자연어 수정 요청을 JSON Patch 명령으로 변환한 뒤 새 JWW로 저장하는 로컬 도구를 만든다. 첫 목표는 지원 범위가 명확한 실제 파일에서 편집이 끝까지 작동하는 데모다. 전체 형식 호환성, 사무소 파일럿, 완성된 승인 시스템을 첫 데모의 선행 조건으로 두지 않는다.

Jw_cad는 결과를 열고 계속 작업하는 프로그램이자 호환성 확인 수단으로 사용한다. 외부변형 연결은 보조 입력 경로로 유지하고 신규 개발의 주 경로에서 내린다.

## 실행 구조

`JWW → Parser → IR(JSON) → Patch → 적용 엔진 → Writer → 새 JWW`

- Parser는 원본 도형과 설정을 읽고, 편집 가능한 객체와 미지원 영역을 구분한다.
- IR에는 객체 ID, 좌표, 레이어/그룹, 단위와 축척, 속성을 담는다. 복원용 원본 바이트와 직렬화 정보는 프로그램이 별도로 보관한다.
- AI는 필요한 객체 문맥을 받고 제한된 수정 명령을 반환한다. 전체 JSON이나 바이너리를 생성하도록 요구하지 않는다.
- 적용 엔진이 실제 좌표 계산과 대상 ID 검사를 수행한다. 첫 명령은 `TranslateEntities(ids, dx, dy)`로 한다.
- Writer는 편집된 결과를 별도 파일에 저장한다. JWW 출력은 단순 JSON 포장 작업이 아니라 형식에 맞춘 직렬화다.
- 프로그램 버전과 파일 내부 버전은 별도 기록한다. 내부 버전, 클래스/schema 및 실제 구조를 함께 사용한다.

## 다음 구현 순서

| 단계 | 실제 산출물 | 확인할 것 |
|---|---|---|
| P0: 작은 왕복 실험 | 선 중심 JWW 샘플, parser/writer 후보 비교, 읽기·쓰기 명령 | 후보가 JWW를 쓸 수 있는지, 무수정 재출력이 가능한지 |
| P1: 최초 편집 | JSON 추출, 지정한 선을 910mm 이동, 새 JWW 출력 | 변경 좌표 재파싱, 다른 속성 유지, Jw_cad에서 정상 열기 |
| P2: 사용 흐름 | 파일 열기, 객체 선택, 전후 미리보기, 다른 이름으로 저장 | 한 파일의 편집을 사용자가 끝까지 수행 |
| P3: AI 연결 | 자연어 → 같은 Patch 계약 | 수동 Patch와 같은 결과, 없는 ID·잘못된 값 거부 |
| P4: 범위 확장 | 문자·원호·치수·블록 및 복잡한 도면 | 기능별 실파일 회귀 사례 추가 |

처음부터 새 파서를 전부 작성하기보다 기존 후보의 읽기/쓰기 경로를 짧게 확인한다. 채택이 빠른 부분은 재사용하고 부족한 writer 부분을 구현한다. 비교 조사만 길게 이어가지 않고, 사용할 후보 또는 직접 구현할 제한 범위를 P0에서 결정한다. 런타임과 UI 전면 교체는 요구하지 않는다.

## 첫 데모의 완료 기준

1. 실제 Jw_cad에서 만든 선 중심 입력 파일을 읽어 객체 목록을 JSON으로 출력한다.
2. 무수정 왕복의 바이트 차이를 검사한다. 단순 원본 복사 성공과 실제 재직렬화 성공을 별도로 기록한다.
3. 선택한 선의 양 끝점을 지정 거리만큼 이동하고 새 JWW를 생성한다.
4. 출력 재파싱으로 좌표와 속성을 대조하고 Jw_cad에서 열어 의도한 변경을 확인한다.
5. 지원한 파일 내부 버전과 객체 종류, 남은 제한을 짧게 기록한다. 모든 파일의 호환성을 주장하지 않는다.

샘플의 무수정 바이트 일치를 우선 목표로 한다. 차이가 있다면 원인과 의미/표시 일치를 확인해 제한된 실험을 계속할 수 있다. 모든 실도면의 바이트 일치를 첫 편집 데모의 조건으로 확대하지 않는다.

## 최소한 유지할 동작

- 입력 원본을 덮어쓰지 않고 새 파일로 출력한다.
- 존재하지 않는 ID, 비유한 좌표, 해석되지 않은 단위는 거부한다.
- 미지원 객체의 바이트 경계나 참조를 보존할 수 없는 파일은 초기 편집 대상에서 제외한다. 작은 지원 샘플로 개발은 계속한다.
- 내부 CLI 실험은 매번 승인창 없이 실행할 수 있다. 사용자 화면은 전후 미리보기와 저장 동작으로 시작한다.
- 별도 승인 토큰 시스템, 다중 공급자, 배포 서명, 사무소 서버, 전 형식 실패 주입은 해당 단계가 필요해질 때 추가한다.

## 기존 작업 처리

기하 검사, 미리보기, 레이어 대응, 프로젝트 기록, 복구 기능은 재사용 후보로 유지한다. I2D 저장 고도화·검토 업무 확장·외부변형 호환성 확대는 주 개발 순서에서 뒤로 옮긴다. 기존 `.jwproject.json` 왕복은 JWW 왕복 검증으로 세지 않는다.

AI 공급자 평가보다 파일 편집 경로를 먼저 연결한다. 벽·창호·방 추론과 자동 설계는 선/문자 편집 경로가 작동한 뒤 확장한다. 현재 작업 트리의 Studio/AI/native 관련 변경은 별도 진행 중 작업일 수 있으므로 보존하고 통합 전에 실제 구현 범위를 확인한다.
