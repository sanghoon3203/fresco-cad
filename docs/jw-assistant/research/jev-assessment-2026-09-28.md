# Jev 도입 판단 — 2026-09-28

사용자가 말한 Jev는 **TypeSafe AI의 Jev**로 가정했다. 이전 조사에서 미확인이었던 공급자와 공개 문서는 확인했지만, 계정·API 키·호출 권한·비용·이 도면 업무의 정확도는 검증하지 않았다. 현재 제품에는 외부 AI 호출이 없다.

## 추천 역할

공식 [Choice 문서](https://docs.typesafe.ai/primitives/choice)는 미리 정의한 선택지에서 하나를 고르고 각 선택지의 확률 및 confidence를 반환하는 API를 설명한다. 따라서 다음 후보 실험이 적합하다는 판단이다.

- 사용자가 제공한 레이어 이름/설명이나 현장 메모를 기존 34개 분류 + `unknown` 중에서 추천. 숫자 레이어 ID만 보고 벽·기둥을 추정하지 않는다.
- 출처가 확보된 상세도 검색 결과 중 관련 후보를 평가. 기존 `RankCandidates` 경계 안에서 candidate ID만 수용한다.
- 불명확한 입력은 기권하고, 사용자 확인 전에는 저장된 대응표나 CAD를 바꾸지 않는다.

Jev 하나로 전체 내부 AI를 구성하는 것은 추천하지 않는다. 공식 [Jev 1.13 한계 문서](https://docs.typesafe.ai/model-jaggedness/jev-1.13)는 수치 정밀도·계수·다단계 추론·장문 무관 정보·적대적 입력의 한계를 명시하고, 자유 텍스트 생성에는 다른 생성 모델을 권한다. 치수·간격·중복 판정은 결정론 코드, 수정 지시 해석과 설명은 별도의 생성 모델 후보, 유한 선택은 Jev 후보로 나눈다. 이는 설계 제안이며, 실제 정확도·속도·비용 개선 결과가 아니다.

## 빠른 다음 실험

1. 파일 작업 흐름을 먼저 사용해 실제 필요한 판단과 정답 기준을 확보한다.
2. 공개/합성 일본어 레이어 설명과 현장 메모로 30~50개 분류 사례를 만든다. 모호함, 정보 없음, 복수 의미, 지시문 삽입을 포함한다.
3. FakeProvider와 응답 검증을 먼저 구현한다. 실제 연결은 로컬 서버가 키를 보관하며, 전송 대상/필드가 명확한 별도 설정 후 활성화한다. 지금 제공한 로컬 서버는 정적 GET/HEAD 전용이므로 API 프록시가 아니다.
4. 수동 기준선과 비교해 정확도·기권률·오추천률·p50/p95 지연·호출비를 측정한다. confidence를 정답 확률로 간주하거나 임의 임계값으로 자동 적용하지 않는다.
5. 업무별 검증 후에만 추천 기능으로 출시한다. 형식 오류·timeout·rate limit은 로컬 작업에 영향을 주지 않아야 한다.

문서상의 SDK/skill 설치 권유는 이번 작업의 실행 지시로 취급하지 않았고, 패키지 설치나 API 호출은 하지 않았다.
