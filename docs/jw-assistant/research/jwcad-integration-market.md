## 결론과 증거 경계

**제품 가설:** 소규모 목조주택 설계사무소의 유료 가치는 ‘중복선 삭제’나 ‘두 도면 비교’ 자체보다, 사무소별 출도 규칙의 재현 가능한 검사, 예외 사유, 승인 전후 증거, 여러 도면의 발행 기록에 있다. 이는 경쟁 기능을 비교한 설계 판단이지 구매 의향이나 절감 시간의 실측 결과가 아니다. Jw_cad에는 이미 데이터 정리, 속성 일괄 변경, 파일 비교, 거리·면적 측정이 있고 외부변형 도구도 많다. 따라서 이 기능을 독점적 새 기능이라고 소개하면 안 된다. 1차 근거는 설치본 공식 도움말 `C:\jww\Jw_cad.chm`의 `menu-edit.html`, `menu-file.html`, `menu-other.html` 및 [공식 변경이력](https://www.jwcad.net/versioninfo.htm)이다.

조사 범위는 공개 공식 변경이력·다운로드, 설치된 공식 도움말·샘플, 외부변형 제작자·공급자 문서와 확인신청 지원 서비스 안내다. `Jw_cad.chm`은 Windows HTML Help의 읽기 전용 압축 해제 후 텍스트를 확인했으며 SHA-256은 `5198fce48cda992c66687dd46bc86496b5ac538832649811b6b1f18dea9cde66`이다. 이 CHM의 파일 수정일은 2026-05-06이므로 10.03.6 실행 동작 자체를 확인한 것은 아니다. 웹의 도움말 재게시 페이지는 검색 가능한 보조 출처일 뿐 Jw 공식 호스트의 1차 근거가 아니다. 로컬 `C:\jww\JW_WIN.EXE`의 파일/제품 버전은 읽기 전용으로 확인한 **10.3.6.0**이고 `JWW_SMPL.BAT`는 27,951바이트, 2007-11-05 수정 파일이다. 공식 변경이력의 최신 10.03.6은 2026-09-05로 표기된다. 이번 조사에서 Jw_cad 실행, 설치 변경, 실제 도면 왕복은 하지 않았다. ## 외부변형 연동: 확인된 계약과 미확인 사항

설치된 `JWW_SMPL.BAT`의 코드페이지 932 텍스트를 읽었다. 이 파일은 `#jww`가 글꼴·임의 문자 크기·블록 기준점/이름·치수 도형을 추가 출력한다고 설명하고, `#cd`는 BAT 위치에 `JWC_TEMP.TXT`를 생성하며 `#hf`는 편집 중 파일의 전체 경로를 기록한다. `#h1`은 선택 범위, `#h4`는 선택 절차 없이 읽을 수 있는 전체 데이터, `#g1`은 모든 레이어그룹을 대상으로 하는 지정이다. `#gn`은 그룹·레이어의 이름과 표시·편집·보호 상태를 내보낸다. 출력 헤더에는 `hk` 축각, `hs` 그룹별 축척, `hn` 선택 범위가 있고, `lg/ly/lc/lt/lw` 및 도형별 레코드가 이어진다. `#bz`는 도면 치수 출력 지정, `bz`는 해당 데이터 마커이며 `lw`는 1/100 mm 단위라고 샘플은 적는다. 레코드에는 문자 기준점·폰트·크기, 치수 결합, 블록 참조, 곡선, 여러 솔리드 형태도 있다. 이 형식은 **선분 네 좌표만 읽어 전체 선택을 재구성할 수 있다는 근거가 아니다.** 샘플의 `hq`는 미실행 반환, `he`는 오류, `hd`는 선택 데이터 삭제 지시다. 샘플 위치: `C:\jww\JWW_SMPL.BAT` 159–214, 289–318, 342–523행. [프로젝트 bridge 기록](../../../addons/jw-assistant/bridge/README.md), [공식 변경이력](https://www.jwcad.net/versioninfo.htm)

10.01.2부터 외부변형으로 **내보내는** 데이터의 Shift-JIS/UTF-8 인코딩은 BAT 인코딩을 따른다. 반환 데이터까지 모든 버전·문자 종류에서 무손실이라고 추론하지 않는다. byte-for-byte 원문 보존, 엄격한 디코딩, 일본어/영어·기종의존 문자·파일 경로 fixture가 필요하다. 알 수 없는 헤더·레코드·속성, decode replacement, 손실 있는 재인코딩이 있으면 쓰기를 닫는다. [공식 10.01.2 변경이력](https://www.jwcad.net/versioninfo.htm)

권장 1차 경로는 **BAT 실행 시점의 선택 데이터 → JWC_TEMP 바이트 캡처 → 불변 snapshot/검사 → 자체 미리보기 → 사용자 승인 → 검증된 반환**이다. 이는 Jw 화면의 상시 선택 변경 이벤트가 아니라 한 번의 snapshot이다. `file=`이 있더라도 열린 도면에 저장되지 않은 변경이 있을 수 있으므로 경로상의 JWW 해시를 현재 캔버스와 동일하다고 보지 않는다. 레이어 보호·숨김 상태 및 `#h1/#h4/#g1`의 실제 선택 범위가 ‘도면 전체 검사’ 주장과 맞는지 확인한다. `#h4`의 ‘읽기 가능한 모든 데이터’가 모든 숨김/보호 데이터 및 블록 내부까지 완전하다고 가정하지 않는다. 프로젝트의 현재 bridge는 `hq`를 보존하는 진단용 캡처이고 실제 Jw 실행·쓰기 검증은 아직 없다. [bridge README](../../../addons/jw-assistant/bridge/README.md), [AFsoft p059](https://afsoft.jp/p-cata/jwwgapp/p059.html)

**no-rewrite gate:** 쓰기 가능한 레코드를 일부만 이해한다는 이유로 전체 `JWC_TEMP.TXT`를 정규화하거나 재생성하지 않는다. 원본 바이트·레코드 순서·미지원 구간을 보존하고, 영향 대상과 반환 계약을 전부 이해하는 세션에서만 최소 패치를 준비한다. `hd`를 써서 선택 전체를 지우고 지원 primitive만 다시 넣는 전략은 블록·치수·곡선·솔리드·폰트·비표시 속성 손실 위험이 있어 금지한다. 취소·timeout·오류 때 도면과 임시 입력이 불변임을 버전별 실기에서 확인하기 전에는 capture/manual 검토만 제공한다. 반환 완료와 Jw 적용 확인, Jw Undo 검증은 별도 상태다. [설치 샘플의 `hd/hq`와 레코드](../../../addons/jw-assistant/bridge/README.md), [프로젝트 아키텍처](../architecture.md)

직접 JWW parser는 별도 경로다. 이를 통해 비선택 파일·발행 세트·백그라운드 목록 검사는 설계 가능하지만, 공개 parser가 버전 미지원 오류를 정의하고 있는 사실 자체가 버전별 포맷 지원의 필요성을 보여 준다. JWW 읽기 성공이 무손실 쓰기나 Jw 내부 엔터티 ID 확보를 뜻하지 않는다. JWW 파일 자체를 자동 교체하는 기능은 별도 포맷, 블록, 글꼴, version round-trip 검증과 백업·복구 게이트 이후로 미룬다. 초기 제품은 외부변형 snapshot과 파일 목록/해시 sidecar를 우선한다. [jww-parser 공개 패키지 API](https://pkg.go.dev/github.com/f4ah6o/jww-parser/jww)

**확인되지 않은 통합 API:** 조사한 공식 변경이력과 설치 샘플에는 외부 앱이 Jw의 현재 selection 이벤트를 구독하거나, 특정 엔터티 ID를 지정해 native select/zoom을 호출한다는 안정적 계약이 없다. AFsoft의 `SendMessage` 도구는 우회 사례일 뿐이다. UI는 경고 클릭 시 자체 preview에서 강조·fit하고, Jw 내부 위치 이동은 검증된 별도 capability가 생길 때만 제공한다. ‘그런 API가 절대로 없다’는 단정도 하지 않는다. [공식 변경이력](https://www.jwcad.net/versioninfo.htm), [AFsoft p059](https://afsoft.jp/p-cata/jwwgapp/p059.html)

## 설치, 회복, 공동 작업

- 설치형 후보는 사용자 쓰기 가능 폴더에 BAT wrapper·애드온 실행파일·설정·로그를 버전별로 둔다. `C:\jww`에 쓰거나 공식 파일을 교체하지 않는다. `#cd` 때문에 `JWC_TEMP.TXT`가 wrapper 옆에 생기므로 그 디렉터리의 권한·잠금·충돌을 확인한다. 여러 Jw 창이나 동시 실행이 같은 wrapper 경로를 쓰면 임시 이름 충돌 가능성을 시험하고, 직렬화하거나 세션별 고유 디렉터리/실행 경로가 실제 Jw에서 동작하는지 검증한다. 벤더 문서에는 `C:\jww` 하위 복사를 요구하는 예가 있으나 당사 제품의 필수 방식으로 따르지 않는다. [설치 샘플/bridge](../../../addons/jw-assistant/bridge/README.md), [Kent 설치 안내](https://www.kentts.co.jp/Jw-cad).
- 설치 시 Jw 실행파일 경로·버전·wrapper 코덱·쓰기 가능한 작업 디렉터리만 검사한다. 실패하면 Jw 기능을 건드리지 않고 wrapper 등록을 제거할 수 있어야 한다. 업데이트는 adapter/version capability를 재평가하고 이전 프로필·검토 기록을 마이그레이션한다. crash 후에는 불완전 결과를 반환하지 않고 고유 세션 폴더의 원본 캡처, 준비 파일, 해시, 처리 상태를 남긴다. 사용자가 원본을 복구하거나 다시 검사할 수 있게 하되 불명확한 성공을 자동 재적용하지 않는다.
- 공유 폴더에서는 **파일 해시가 snapshot 승인 시점과 같아도 다른 사용자의 미저장 Jw 창은 감지하지 못한다.** Jw 바깥에서 JWW를 직접 덮어쓰지 않으며, 발행 기록에는 기준 파일의 경로·바이트 해시·mtime·크기와 관찰 시각을 함께 남긴다. 재검사/반환 직전 해시와 세션 ID를 확인하고 달라지면 stale 처리한다. SMB/OneDrive의 동기화·잠금·오프라인 충돌, 두 사용자 동시 저장, 별칭 경로/대소문자, 네트워크 끊김을 fixture로 재현한다. 이것은 동시 편집 병합 또는 분산 transaction 보장이 아니다.

## 실제 도면 fixture와 출시 전 판정표

| fixture 묶음 | 확인할 관찰 결과 |
|---|---|
| 정상·취소·실패 | 10.3.6.0의 복제 도면에서 `hq`, `he`, 창닫기, timeout, crash, 읽기 잠금·권한 거부를 각각 실행. 캡처와 source의 해시, 원본 JWW, 화면 도형·속성, Undo/Redo를 전후 비교. `hd`는 승인된 쓰기 게이트에서 격리된 폐기 fixture로만 시험. |
| 코덱·경로 | CP932/UTF-8 wrapper, 일본어·ASCII·기종의존 문자·폰트명, 일본어·공백·긴 경로, 비정상 바이트 및 파일 이름; 엄격한 decode/encode와 순서·바이트 보존 검증. |
| 좌표·척도 | 그룹 0–F마다 다른 축척, `hk` 축각, `#0`/선택 기준 원점, 음수·매우 큰·소수 좌표, `#bz`/`bz` 치수, 종이 치수 vs 실제 치수, 선폭 1/100 mm, mm와 m 표기 및 실측 거리의 역변환. |
| 개체·속성 | 선·원·호·타원·점/마커·가로/세로/치수문자·폰트·임의 크기·基点, `msg` 치수 묶음, `BL` 회전/배율/중첩 블록, `pl` 곡선, 솔리드 종류·任意色, `z1–z5` 속성, 미지 레코드. 중복선의 역방향 끝점과 다른 색/종/레이어는 구분. |
| 선택·레이어 | `#h1/#h2/#h3/#h4`, `#g0/#g1/#gn`, 현재/숨김/표시전용/보호 그룹·레이어, 블록 내부, 경계에 걸친 개체, 선택 외 데이터. 읽지 못한 범위가 있으면 검사 결과에 범위를 명시하고 ‘전체 완료’ 표시 금지. |
| 비교·공동 작업 | 같은 도면의 native `ファイル比較`와 결과 대조, 복제 도형·이동·회전·속성만 변경·여러 후보 매칭; 파일 공유와 두 창 동시 외부변형, 원본 저장 전후, 다른 사용자의 저장·잠금·동기화 충돌. snapshot/plan/profile 해시가 바뀌면 승인 폐기. |
| 설치·복구 | Jw 설치 위치 변경, 일반 사용자 권한, wrapper 별도 폴더, 버전 업그레이드, JWC_TEMP 충돌, 네트워크 실패, 임시파일 반쪽 쓰기, 디스크 부족, 재시작 후 세션 회복 및 제거. |

각 항목은 `not-tested / read-only / preview / write-verified`로 버전별 기록한다. 현재 프로젝트에는 합성 규칙 엔진과 읽기 전용 bridge 코드가 있지만, **Jw 실기 연결 및 도면 쓰기 인증은 없다.** 실제 고객 도면은 비식별화·별도 동의·복제본으로 테스트하고, 파일럿 시간 절감/정밀도는 그때 측정한다. [제품 요구사항](../requirements.md), [bridge README](../../../addons/jw-assistant/bridge/README.md)
