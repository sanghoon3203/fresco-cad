# 상세 레이어와 현장 마감 정보 계약

2026-09-25. 소규모 목조주택 사무소용 초기 템플릿이며 업계 공통 표준이라는 주장은 하지 않는다.

## 참조 자료에서 반영한 점

사용자가 지정한 로컬 자료의 주택 CAD 연습 PDF 3페이지(평면·4방향 입면·단면 상세)를 렌더링하여 읽었다. JWF 5개는 CP932로 레이어 이름을 확인했고 JWW 5개는 목록만 확인했다. JWW 내부 기하를 해석하거나 이 자료를 승인된 현장 시공도서로 검증한 것은 아니다. 별도 구조 연습 PDF는 목록만 확인했다.

도면을 이해하는 데 통り芯, FL/GL, 창호 번호, 마감과 바탕의 층 구성, 상세 참조가 함께 필요했다. JWF는 주로 숫자 레이어와 하ッチ·색칠·문자·치수·보조선 이름을 사용했다. 따라서 숫자만으로 외벽·내벽 등을 추론하지 않는다. 원본 도면·설정·렌더링 이미지는 Git에 포함하지 않는다.

## 34개 기본 분류

외벽, 내벽/칸막이, 기둥, 보, 통り芯, 기초, 바닥틀, 계단, 가구, 주방, 변기, 세면/싱크, 욕조, 창, 문, 붙박이 수납, 환기/공조, 급배수, 전기/조명, 바닥 마감, 벽 마감, 천장 마감, 걸레받이/트림, 방수, 단열/기밀, 지붕/처마, 접합부/실링, 마감 바탕, 관통/점검구, 해치, 색칠, 문자, 치수, 보조선.

`field/standards.mjs`가 분류 ID·일영 명칭·제안 번호를 제공한다. 초기 활성 대응표는 비어 있다. 사용자가 **초기안 입력 → 실제 그룹:레이어로 조정 → 대응 확인 후 저장**해야 활성화된다. 대응하지 않은 레이어는 미분류로 남긴다. 같은 실제 레이어를 두 분류에 할당하면 저장을 거부한다. 한 분류에 여러 레이어는 허용한다. 기존 CAD의 이름이나 번호는 수정하지 않는다.

의미 분류 대응표와 기하 검사 허용 레이어 목록은 별도 설정이다. 분류를 저장했다고 허용 레이어 규칙을 자동 변경하지 않는다. 기존 프로젝트에서 한 레이어에 여러 종류가 혼재하면 해당 레이어를 단일 의미로 억지 분류하지 말고 미분류로 유지한다. 향후 객체 단위 확인으로 보완한다.

## 현장 확인 메모

입력은 사용자가 확인한 분류와 다음 12개 항목이다: 층/방/축/면, 도면 번호/개정, 상세/시방 참조, 마감재/품번/색, 바탕/층 구성, 두께/폭/단위, 기준 높이, 단부/접합부/트림, 시공 방법/순서, 설비/창호 간 조정, 검사 방법/시점, 담당자/확인처.

엔진은 빈 항목을 결정론적으로 검출한다. 입력 내용의 물리적·법적 타당성, 제품 조합, 방수 성능, 내화 성능, 구조 안전을 판정하지 않는다. 모두 입력해도 상태는 `needs-designer-review`이며 시공 승인으로 전환하지 않는다. LLM은 현재 호출하지 않고 사양을 임의 생성하지 않는다.

UI에서 부분 작성 메모도 저장하고, 누락 항목이 표시된 일본어/영어 인계 텍스트를 복사할 수 있다. 이 단계의 메모는 CAD 객체/방에 자동 귀속된 것이 아니며 위치를 직접 적는다. **문맥 안의 위치별 복수 카드, 전체 최대 100장**을 지원한다. 각 카드에 안정된 ID를 부여한다. 문맥은 원본 SHA·해석 조건·검사 프로필 키에 분류 대응표까지 포함한다. 소스·기준·대응표를 바꾸면 이전 메모를 새 조건에 자동 이월하지 않는다.

## 저장·복구·다음 단계

브라우저 origin별 localStorage에 분류와 메모를 보관한다. 필드당 600자, JSON 2 MiB 상한. 한 탭 순차 사용이며 이전 정상본을 먼저 보존한다. 손상·용량 초과·오래된 revision은 저장 실패로 처리한다. 현재 JSON과 이전 백업을 화면에서 보존하고, v1/v2 JSON 붙여넣기 또는 로컬 파일 선택 → 검증 미리보기 → 명시적 교체로 정상 저장소를 복원한다. v1은 읽을 때 메모리에서만 변환하고 저장할 때 v2로 기록한다. 일반 저장은 손상 primary 덮어쓰기를 차단한다. I2C의 명시적 복구 경로는 원문을 별도 보관하고 정상 backup을 유지한 뒤 복원한다. [복구 계약](backup-recovery.md). 원본 도면 바이트는 저장하지 않는다. 현장 메모 초안은 세션 메모리에서 문맥·카드별로 보존한다. 다른 도면/그룹으로 이동해도 원래 조건으로 일괄 저장할 수 있다. 페이지 이탈 방지 핸들러는 보조 수단이며 강제 종료 복구를 보장하지 않는다. 사무소 검토 판단 초안은 별도다.

사무소 검토 기록 복원과 손상 저장소 원문 보존 복구는 [Sprint 06](sprint-06-i2c-report.md)에서 구현했다. 다음 구현 게이트는 사무소별 파일 작업 공간, 실기/파일럿 검증, 객체/방에 대한 확인된 연결과 도면 개정 참조다. 실제 레이어 생성/분리와 마감 상세 작도는 Jw 쓰기·Undo·무손실 검증을 통과한 후 도입한다. 각 스프린트는 코드/시험/보고서를 기능별 커밋으로 분리해 GitHub에 푸시하고 개인 원본 자료는 제외한다.
