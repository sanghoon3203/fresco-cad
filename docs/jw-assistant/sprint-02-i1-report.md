# I1 구현 스프린트 보고 — 실제 캡처 읽기 전용 검사

작성일: 2026-09-24. 판정: **읽기 전용 가져오기 구현과 제한된 실기 검증 완료. I1 전체 호환성 게이트와 배포 승인은 미완료.**

이제 Jw_cad에서 진단용으로 캡처한 JWC_TEMP를 로컬 화면에서 가져와 선을 검사할 수 있다. 실제 업무 도면을 수정하거나 클라우드로 보내지 않는다. 기존 합성 데모에서만 수정안 적용과 되돌리기를 사용할 수 있다.

## 구현 결과

| 범위 | 결과 |
|---|---|
| 입력 어댑터 | 명시적 UTF-8/Shift_JIS 디코딩, 8 MiB 제한, 원본 바이트 SHA-256, 선·그룹·레이어·색·선종·선폭 처리 |
| 단위 | 사용자 확인 전 검사 보류. model-mm는 그대로, paper-mm는 선택 그룹 축척 적용. 범위를 벗어나는 좌표 거부 |

| 보수적 처리 | 회전/축 정보 누락, 중복·뒤늦은 핵심 헤더, 미검증 z 속성, 복합 도형은 검사 차단 |

| 결과 구분 | 미검사를 발견 0건과 구분. 새 파일·해석 변경 시 이전 결과와 수정안을 비움. 취소된 비동기 가져오기 결과 무시 |

회사별 CAD 규칙은 이번 입력으로 추론하지 않는다. 숫자 레이어를 그대로 보존하고, 입력에 존재하는 레이어를 허용하는 프로필을 사용한다. 따라서 현재 가져오기 결과의 레이어 검사는 회사 표준 준수 판정이 아니다.

## 실제 Jw 확인

기존에 열려 있던 업무 도면과 별도로 Jw 창을 실행하여 빈 도면에 수평 10,000 mm 선 하나를 직접 작성했다. 상태 표시줄에서 길이 `10,000.000`, 축척 `1/100`을 확인했다. 진단 파일은 `C:\Users\Public\Fresco-I1-20260924`에 복사하여 설치 폴더를 수정하지 않았다.

| 시험 | 관측 |
|---|---|
| Jw 버전 | `10.3.6.0`, 실행 파일 SHA-256 `9f8daae501f85c5e80de39cd9339cab17322e655553720288d3b5cfb1b7fa2fc` |
| UTF8 이름의 BAT, 00:28:15 UTC | Jw 파일 선택창에서 S-JIS로 분류. 안내 문자가 깨졌고 실제 결과는 CP932. **UTF-8 호환성 실패** |
| SJIS BAT, 00:30:02 UTC | 일본어 안내 정상, CP932 캡처 생성 |
| 두 캡처 | 모두 389바이트. 원본/복사본 SHA-256 동일: `c849c5ba847b13e0f432428e7e20dd68f1bc4cba7d5ef11f34d1f99318d6f656` |
| 좌표 | `hs` 전부 100, `hk 0`, `lg0`, `ly0`; 선 좌표 `-5000 0 5000 0`. `bz` 없이 이미 실치수 |
| Jw 반환 | 두 번 모두 `未実行` 표시, 선이 화면에 유지됨. 저장 파일 비교·전체 속성·Undo 이력 불변까지 검증한 것은 아님 |

이 증거 때문에 축척만 보고 좌표에 100을 곱하지 않는다. 단위 확인을 유지하고, 실제 캡처를 바이트 그대로 [회귀 fixture](../../addons/jw-assistant/fixtures/jwc-temp/jw-10.3.6-line-10000-shift-jis.txt)로 보관했다. Git 줄바꿈 정규화도 이 파일에는 적용하지 않는다. 이는 업무 도면이 아닌 이번 시험용 합성 도면의 실제 호스트 출력이다.

## 검증

- `node --test addons/jw-assistant/tests/*.test.mjs`: **28/28 통과**. 단위 변환, 그룹 분리, 잘못된 헤더/숫자/코덱, 복합 데이터 거부, 실제 CP932 캡처, 기존 검사/수정 계약, 번역 키, 서버 접근 경계를 포함한다.
- `pwsh -NoProfile -File tests/bridge_capture.test.ps1`: 통과. 브리지 검토 에이전트가 실행했으며 원본 읽기 전용 복사·해시·잠금 거부 시험이다.
- 실제 브라우저: 캡처 선택 → 단위 미확인 보류 → model-mm 확인 → 한 선 표시, 변경 버튼 비활성화를 확인했다.
- 일본어에서 영어로 전환 후 JSON 보고서의 `jwc-temp-read-only`, `jwCadConnected:false`, `writeAllowed:false`, 원본 해시를 확인했다.
- 혼합 그룹 합성 입력: 그룹 선택 전 검사 보류, 그룹 0 선택 후 중복 1건, 제외 선 1개, 미지원 원 1개를 표시했다.
- 복합 레코드 합성 입력: 파싱 중단 위치와 `Not checked` 표시, 좌표 단위를 확인한 뒤에도 차단 유지를 확인했다.
- UI 콘솔 오류 조회는 빈 결과였다. 전체 화면 리더·DPI·대형 도면 UI 성능 검증은 하지 않았다.
- 마지막 화면에서 가로폭 771px와 콘텐츠폭 771px가 일치했고, 실제 캡처 선 1개와 수정 버튼 전체 비활성화를 확인했다. 합성 데모로 돌아가면 기존 3건의 결과가 복원되었다.

초기 단위 시험 두 개에는 `hk`가 빠져 있었다. 축 정보 누락 차단을 추가한 뒤 명시적인 `hk 0` fixture로 수정했고, 누락 시 차단되는 시험도 별도로 통과했다.

## 남은 게이트와 다음 순서

1. UTF-8 BAT 인식 방식 수정과 일본어 문자 왕복 재시험. 현 시점에는 SJIS 경로만 제한적으로 확인했다.
2. Jw 창마다 임시파일 디렉터리를 분리하는 실행기와 동시 실행 시험. 현재 helper의 파일 잠금은 실행 전에 생기는 공용 임시파일 충돌까지 막지 못한다.
3. 그룹별 다른 축척, 회전, 공백/일본어 경로, 취소·실패, 저장 파일·속성 불변 확인. 한 선 시험을 전체 호환성으로 확대 해석하지 않는다.
4. 완료된 캡처 번들의 metadata/hash를 검증하는 입력 경계. 현재는 사용자가 고른 원시 파일이며 호스트 출처와 생성 시각을 인증하지 않는다.
5. 이후 I2에서 회사 프로필·검토 상태 저장·수정업무 기록·파일럿 실행 묶음. 실제 사무소 업무 관찰 자료는 아직 미확보다.

I1-01 계약과 I1-04 UI는 구현했다. I1-02 파서는 제한된 선 형식에서 구현했으며 확장 호환성 시험은 남았다. I1-03 세션 격리와 I1-05 전체 실기 행렬은 미완료, I1-06 현장 관찰은 대기다. AI API/BYOK, 법규·구조 검토, JWW writer, 설치/업데이트는 이번 결과에 포함되지 않는다.

## 작업 인계

GPT-6 Sol이 파서와 브리지 검토, GPT-6 Luna가 UI 초안을 병렬로 진행했다. 에이전트 사용량 제한 이후 루트가 상태 전환·차단 처리·통합·실기·보고를 마무리했다. 추가 API 비용이 드는 제품 호출은 실행하지 않았다.
