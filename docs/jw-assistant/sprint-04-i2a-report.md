# Sprint 04 / I2A — 사무소 검토 기록·상세 레이어·현장 확인

날짜: 2026-09-25. 결과: 읽기 전용 시제품의 이번 구현 범위 완료. 상용 배포/실제 CAD 수정 완료를 의미하지 않는다.

## 변경

- 사무소 검사 프로필을 명시적으로 저장하고 버전별로 재검사한다.
- 검토 중/제외(사유 필수)/재확인 상태, 메모, 일시를 로컬에 저장한다. 제외해도 검출 항목은 남는다.
- 원본·문자 코드·단위·그룹·전체 검사 규칙에 묶인 문맥 키로 이전 판단이 다른 결과에 연결되는 것을 차단한다.
- CSV의 수식 실행 방지, 현재 JSON 및 이전 정상 백업 표시, 손상/용량/오래된 revision 거부를 추가했다.
- 34개 상세 레이어 분류 템플릿, 명시적 숫자 레이어 대응표, 미분류 표시, 중복 할당 거부를 추가했다.
- 현장 메모 12개 항목, 누락 검사, 일영 인계 텍스트, 로컬 저장/재열기를 추가했다. 모든 항목을 채워도 설계자 확인이 필요하다.
- 자체 리뷰에서 비동기 문맥 계산 경쟁, 데모 전환 후 검토 문맥 잔류, 빈 수치 입력, 오류가 접힌 패널에 숨는 문제, 설정 버튼의 잘못된 focus 연결을 수정했다.
- Git 저장 시 BAT의 CRLF가 정규화되는 문제를 발견해 바이트 보존 속성과 재스테이징으로 수정했다. 실제 캡처 fixture와 SJIS/UTF8 래퍼 3개 모두 Git blob과 작업 파일이 바이트 단위로 같음을 확인했다.

## 참조 검토

지정 로컬 폴더의 주택 연습 PDF 3페이지를 시각적으로 확인하고 JWF 5개의 레이어 이름을 읽었다. JWW 5개는 목록 확인만 했다. 자료가 교육용이므로 일반 사무소의 확정 표준이나 승인된 시공도서로 일반화하지 않았다. 숫자 레이어가 건축 의미를 보장하지 않는다는 점을 초기 대응표 비활성 정책에 반영했다. 원본과 렌더링 결과는 저장소 밖에 유지했다. [상세 계약](field-coordination.md).

## 검증

`node --test addons/jw-assistant/tests/*.test.mjs`: **47/47 통과**. 기하·가져오기·캡처 검증·일영 카탈로그·리뷰 저장/CSV·현장 분류/누락/문맥·정적 서버 범위를 포함한다.

브라우저에서 합성 mixed-group 파일을 UTF-8/model-mm/group 0으로 읽고 다음을 확인했다.

- 중복선 1건, 실제 가져오기 수정 버튼 비활성.
- 초기 분류안을 확인 저장한 뒤 `0:0 → 외벽` 표시.
- 창호 분류의 현장 메모와 제외 사유 저장, 영어 전환 시 값 보존.
- 새로고침 후 같은 파일/조건을 다시 지정하면 두 종류 메모 모두 복원.
- 검사 프로필 변경 후 이전 메모를 새 결과에 이월하지 않음.
- 키보드로 수치 필드를 비우면 저장 거부 및 오류 표시. 브라우저 자동화의 숫자 `fill('')`가 값을 비우지 않아 실제 키보드 삭제로 확인했다.
- 이 흐름의 브라우저 오류/경고 로그 없음. 데스크톱 화면 시각 확인. 좁은 창, Narrator, IME, 실제 Excel 재열기, 실무자 사용성은 이번 검증 범위 밖이다.

이번 단계는 실제 Jw 네이티브 조작을 추가하지 않았다. 이전 I1B의 Jw 실기와 Windows bridge 근거는 [Sprint 03](sprint-03-i1b-report.md)에 구분해 보존했다.

## 모듈과 작업 분담

기하 core / Jw adapter / capture bridge / review / field / storage / UI를 분리했다. GPT-6 Luna가 리뷰 UI 초안을 작성했고 루트가 저장 계약·통합·현장 모듈·수정·검증을 완료했다. GPT-6 Sol 저장 작업은 시작 지연으로 루트가 회수했다. Luna 후속 수정은 사용량 제한으로 실행되지 않아 루트가 처리했다. 실행되지 않은 에이전트 검토를 완료로 계산하지 않는다.

SEED/Apple 계열 참조 skill의 출처와 라이선스는 `tools/skills/provenance.json`에 있다. 현재 구현은 자체 DOM/CSS 시제품이며 SEED React 컴포넌트 도입이나 Apple 공식 인증을 주장하지 않는다.

## 한계와 다음 게이트

localStorage는 단일 탭 순차 시제품 저장이다. 다중 사용자 원자적 DB, 전체 감사 이력, 복구 업로드 UI가 아니다. 현장 메모는 검사 문맥당 1장이다. 자동 재료 추론, JWW 직접 읽기/쓰기, 레이어 재배치, 마감 상세 작도, 법규/구조 판정, AI API 호출은 미구현이다.

다음 우선순위는 복수 위치별 현장 카드·미저장 전환 안내·JSON 복구·실제 사무소 자료의 확인된 레이어 매핑이다. 이후 host 쓰기/Undo 합격 게이트를 통과해야 실제 CAD 변경을 연결한다.

GitHub 저장은 사용자 요청에 따라 core/bridge, review/field, UI, 문서/참조 skill의 기능별 커밋으로 구성한다. 원격 푸시 결과는 최종 사용자 보고에서 커밋과 함께 확인한다.
