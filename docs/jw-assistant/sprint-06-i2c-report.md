## 이번 구현

- 사무소 프로필과 검토 판단 백업을 JSON 파일/텍스트에서 검증한 뒤 전체 복원한다. 현장 분류·메모에도 같은 복원 화면을 사용한다.
- 정상 저장본을 복원하면 직전 정상본을 backup으로 보존한다. 손상되거나 미래 형식인 primary는 원문을 별도 보관한 후 복원하고 기존 정상 backup을 유지한다.
- 미리보기 데이터의 변경, 다른 store의 미리보기, 재사용, 같은 revision의 실제 내용 변경, 빈 저장소의 중간 생성을 거부한다.
- 미저장 규칙·현재 검토 입력·현장 초안이 영향을 받는 복원을 차단한다. 원문/보관 원본 다운로드, 전체 교체 내용 표시, 오류별 안내를 일본어·영어로 제공한다.
- 잘못된 용량·형식, 백업/primary 기록 실패, 보관소 손상·상한을 검증한다. 손상 데이터가 화면에서 정상 revision 0으로 보이지 않도록 수정했다.

상세 제한과 데이터 계약: [백업 복구](backup-recovery.md).

## 검증

저장소 루트에서 `node --test addons/jw-assistant/tests/*.test.mjs`: **67/67 통과**. 새 검사 13개는 두 저장 영역의 정상 복원, 원문 보존, one-use/store-bound preview, 충돌, 용량 실패, 실패 후 재시도, archive 제한과 legacy 변환을 다룬다. 최종 실행은 변경된 미리보기 불변성 검사도 포함했다.

브라우저는 기존 사용 데이터와 구분되는 로컬 포트 `54726`에서 합성 JSON만 사용했다.

1. 사무소 프로필/검토 1건 미리보기 → 적용 → 현재 JSON에서 revision 1과 기록 일치 확인.
2. 미리보기 이후 JSON 수정 시 적용 비활성. 잘못된 JSON은 거부하고 일영 오류 안내 확인.
3. 미저장 사무소 수치 규칙 변경 시 복원 차단, 명시적 초안 되돌리기 후 재검증/복원 확인.
4. 정상 재복원 후 직전 backup 불러오기와 내용 요약 확인.
5. 현장 카드 1장·분류 1개 복원 후 현재 JSON과 revision 확인. 미저장 분류 변경 시 적용 차단.
6. 현장 JSON 다운로드의 실제 파일(470 bytes)을 확인하고 같은 파일을 파일 선택기로 다시 읽어 검증 미리보기 통과. IAB의 download 이벤트 대기는 시간 초과했으나 파일 생성과 재입력으로 결과를 확인했다.
7. 최종 복원 성공 화면을 시각 확인. 해당 브라우저 흐름에서 error/warn 로그 없음.

손상 저장소와 실패 주입은 메모리 storage 자동 검사로 검증했다. 실제 사용자 브라우저 저장소를 고의 손상하지 않았으며, 손상 primary가 있는 앱 재시작의 브라우저 실기, 좁은 화면/IME/Narrator, 다중 탭 경쟁, 실무 JWW/Undo, 네이티브 Windows 설치는 이번 수락 범위 밖이다. 네이티브 bridge/C++ 코드는 변경하지 않아 해당 과거 시험을 새로 실행했다고 주장하지 않는다.

## 예시 자료

`OneDrive/Desktop/臨時`에서 기존에 참조한 주택 연습 자료(JWW 5개, JWF 5개, 평면·입면·단면 PDF)와 구조/계획 연습 PDF의 존재를 다시 확인했다. 이번 복구 기능에는 추가 도면 해석이 필요하지 않아 원본 파일은 수정하거나 저장소에 복사하지 않았다. JWW 내부 의미와 실제 사무소 승인 기준을 검증했다는 뜻은 아니다.

## 다음 계획 조정

우선순위를 **I2D 파일 기반 작업 공간 → I1 실기/사무소 파일럿 잔여 게이트 → 확인된 객체·방 연결 → I3 FakeProvider·지시 추출 평가 → BYOK**로 정리한다. I1 실기 자료 수집은 파일 작업 공간 개발과 독립적으로 진행할 수 있다. AI나 CAD writer 구현만 앞당기면 아직 미확인인 문맥과 저장 실패를 더 복잡하게 만들 수 있다.

- I2D: 프로젝트 ID와 원본 snapshot provenance를 가진 명시적 작업 공간 형식, 검토+현장 백업 간 대응, 임시 파일 검증·원자 교체·직전 정상본·실패 복구. 현재 JSON 다운로드는 이 게이트의 완료가 아니다.
- I1/파일럿: 복제 도면으로 mixed scale/rotation/cancel/두 창, 일반 사용자 설치·제거·복구, 실제 레이어 매핑과 오탐/검토 시간 측정. 교육용 자료를 사무소 표준으로 일반화하지 않는다.
- 의미 연결: 확인된 위치/객체만 묶고 도면 변경 시 재확인 상태로 만든다. 자동 방 인식이라고 설명하지 않는다.
- I3: 계정 없이 동작하는 FakeProvider와 원문 span/불확실성/송신 범위·예산·실패 평가를 먼저 고정한다. 실제 공급자 연결은 그 이후다.

스프린트 변경은 저장/시험, UI, 문서로 나눠 커밋한다. push의 성공 여부는 원격 branch SHA와 로컬 HEAD 일치를 확인한 뒤 보고한다. 개인 도면과 자격정보는 변경 목록에 포함하지 않는다.
