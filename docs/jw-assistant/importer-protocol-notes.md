# JWC_TEMP read-only importer, sprint I1

The parser is based on the read-side record listing in the installed `C:\jww\JWW_SMPL.BAT` and one manually drawn test capture from Jw_cad 10.3.6. The test capture is a blank drawing with a single horizontal 10,000 mm line, drawn specifically for this sprint; it is not a customer drawing. The adapter is bounded and read-only; `coverage.writeAllowed` is always `false`.

The documented stream begins with `hq`; `file=` may reveal a source filename and is discarded. `hk` supplies an axis angle and `hs` has 16 scale numbers. The numeric headers `hcw`, `hch`, `hcd`, `hcc`, `hn`, `hzs`, `hzk`, and `hpN` are validated and ignored. `lg` and `ly` select hexadecimal group and layer. `lc`, `lt`, and `lw` are supported style state. Attribute records `z1`–`z5` block the import pending host fixtures that establish their lifetime and grouping semantics. Font selection `cnN` and `cn"...` and a standalone `#` section separator are also recognized. Bare four-number rows are line endpoints. `ci`, `pt`, and text records are known nonline records and omitted with partial coverage. Other commands, including `msg`, `pl`, `sl`, `sc`, relative-coordinate commands, block commands, or unknown records, block the whole snapshot. Parsing stops at the first unknown command, so later numeric rows cannot be mined as lines.

The core Snapshot v1 requires model millimetre coordinates and has only `layer`, `color`, and `lineType` style fields. The adapter emits a snapshot only with explicit `user-confirmed` paper-mm or model-mm calibration, a single selected group, and no blocking record. Paper-mm coordinates are multiplied by that group's `hs` scale; model-mm coordinates are left unchanged. For example, a 10 mm paper line at 1:100 becomes 1000 mm in the snapshot. A `bz` marker conflicts with paper-mm calibration. A nonzero `hk` blocks the snapshot until its coordinate relationship is validated. The adapter does not rotate points. Group/layer IDs become numeric strings such as `1:2`; no architectural layer meaning is inferred. Color, line type and width are encoded in the available core style fields so the duplicate checker does not merge lines with different known styles. Snapshot IDs are local to the import.

The exact-byte fixture is [`addons/jw-assistant/fixtures/jwc-temp/jw-10.3.6-line-10000-shift-jis.txt`](../../addons/jw-assistant/fixtures/jwc-temp/jw-10.3.6-line-10000-shift-jis.txt), SHA-256 `c849c5ba847b13e0f432428e7e20dd68f1bc4cba7d5ef11f34d1f99318d6f656`. It was captured on 2026-09-24 from Jw_cad 10.3.6, blank drawing at 1:100; Jw's status displayed `10,000.000` for the native dimension. The CP932 stream is 389 bytes, has `hs` values all 100, `lg0`, `ly0`, `lc2`, `lt1`, `cn2`, `cn"$<ＭＳ ゴシック>`, then `#` and `-5000 0 5000 0`. Thus at least this ordinary capture provides model-mm coordinates without `bz`; absence of `bz` cannot prove paper-mm. Its exact scale indexing beyond `lg0` remains to be checked.

Open capture checks: verify `hs` indexing for groups 1–F, whether Jw emits a numeric line before group/layer state, and whether nonzero `hk` has already been applied to exported endpoints. Also verify which optional headers and style commands occur in other ordinary selections. Any such record should be explicitly added to the parser only after capture evidence and a regression fixture.

Limits are 8 MiB source bytes, 150,000 physical lines, 16,384 characters per line, 100,000 selected line entities, and absolute coordinate magnitude of 1e9. Strict `TextDecoder` with the caller's explicit UTF-8 or Shift_JIS choice rejects invalid input. The adapter hashes original bytes with WebCrypto SHA-256. Reports carry counts, line numbers, structural metadata, and the digest; they do not contain source paths or text payloads.
